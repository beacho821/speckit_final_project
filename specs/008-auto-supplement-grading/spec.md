# 功能規格：自動補答與逐筆改判

**功能目錄**　`specs/008-auto-supplement-grading`  
**建立日期**　2026-11-24  
**狀態**　草案  
**需求來源**　老師結束搶答後，由系統引用原先設定的標準答案補答。老師可查看各組提交的原文，並透過每筆作答旁的「錯誤」與「正確」按鈕更正判分。

## 釐清紀錄

### 2026-11-24 問答

- Q: 如果升級時有一個尚未定案的舊回合，老師已儲存人工補答，而該子題仍無人答對，定案時應採用哪個答案？ → A: 保留已儲存的人工補答。仍需補答且沒有已儲存人工補答的子題，才自動引用開題時的標準答案。

## 使用情境與驗收

### 使用情境 1 — 停止收件後自動補答（P1）

老師停止收件即可在審核畫面看到仍無具資格組別答對的子題及其自動補答，並能按既有流程定案。全部未答或答錯的回合也能完成結算。

**獨立驗收**　準備兩個子題，每題至少設定一個標準答案，分別測試無人送答、只有一題答對及兩題分別有人答對。

1. **假設**兩個子題皆無人送答，且第一個子題依序設定了「中央處理器」與「CPU」，**當**老師停止收件，**則**兩題立即各顯示一筆自動補答，第一個子題顯示「中央處理器」。老師可直接確認定案，補答欄位的輸入、確認與儲存操作均為零，結果為無勝組。（FR-001、FR-002、FR-003）
2. **假設**只有第一個子題有具資格組別答對，**當**老師停止收件，**則**只有第二個子題產生自動補答。定案後，對應子題的教師結果、學生已公布結果及 CSV 補答列均反映相同內容。（FR-001、FR-003、FR-009）
3. **假設**兩個子題分別由不同具資格組別答對，**當**老師停止收件並定案，**則**沒有補答，且沒有單一組別全對，因此顯示無勝組。（FR-001、FR-008）
4. **假設**舊回合尚未定案，兩個子題仍需補答，第一個子題已有與標準答案不同的已儲存人工補答，第二個子題尚無補答，**當**老師重新開啟審核並定案，**則**第一個子題保留人工補答原文，第二個子題自動引用標準答案。老師毋須為任一子題重新輸入或儲存補答，公布結果及 CSV 皆採用各自的補答。（FR-001 至 FR-003、FR-009）

### 使用情境 2 — 老師查看原答並逐筆改判（P1）

老師在定案前看見學生實際送出的答案，能對某一組的某個子題改判。老師可以更正誤判，也能在發現選錯時改回。

**獨立驗收**　讓兩組各提交兩個子題，其中一筆合理同義回答被自動判為錯誤。老師停止收件後，只改判該筆，再核對其他作答、補答與勝組。

1. **假設**第一組與第二組都已送出，**當**老師停止收件，**則**老師能依組別、完整題號與收件順位辨識每筆原答。每筆已提交的答案旁都有「錯誤」與「正確」兩個可用鍵盤操作的按鈕，顯示目前選中狀態。未送答的組別無可改判的答案按鈕。（FR-004、FR-005）
2. **假設**只有第二組的第二個子題被自動判錯，且該子題原先需要自動補答，**當**老師選該筆的「正確」，**則**只有該筆的目前判定變為正確，原答與自動判分仍可辨識。審核畫面重算該子題，若這筆成為具資格的正確作答，就移除該子題的自動補答。若再選「錯誤」，且其餘具資格作答都錯誤，則自動補答重新出現。（FR-005、FR-006）
3. **假設**改判使某組成為最早送出且符合資格的全對組，**當**老師儲存判分並確認定案，**則**該組成為勝組。結果反映老師儲存的判定，沒有改變原文字、收件時間或順位。（FR-007、FR-008）
4. **假設**兩個教師分頁同時審核同一回合，且一頁已儲存較新的修改，**當**另一頁嘗試儲存過時的修改，**則**保留當前草稿，提示核對最新審核內容。未核對前不得覆蓋已存修改或定案。（FR-007、FR-010）

### 邊界情況

- 同一子題的多個標準答案都可參與現行自動判分。自動補答從該回合開題時的設定選第一個非空白答案，並採用已設定的文字。
- 已取消資格的組別即使改成答對，也不會消除該子題的自動補答或取得勝組資格。恢復資格後依有效判定重新計算。
- 學生未送答時，老師不會看到虛構的原答。開題沿用現有的標準答案必填條件。若仍需補答的舊子題沒有已儲存的人工補答，也缺少可引用的標準答案，畫面標明沒有可引用的答案，教師仍可確認定案，結果不產生虛構的補答。
- 只有原本已提交的組別與子題組合可改判。重複點擊已選中的判定不得增加修改。定案、回合失效或身分無權限時，拒絕改判、說明原因及下一步，且不變更結果。
- 已定案的舊回合保留原本的判分、補答及勝組。先前已定案的人工補答依原內容顯示。

## 需求

### 功能需求

| 編號 | 可驗收行為 |
| --- | --- |
| FR-001 | 停止收件後，系統逐題判斷是否有具資格的組別答對。仍需補答的子題若已有舊回合已儲存的人工補答，須保留原文並標明「老師補答」。其餘仍需補答的子題自動引用該子題的標準答案，並在教師審核處按完整題號顯示及標明「自動補答」。 |
| FR-002 | 自動補答依該回合開題時的標準答案設定順序，採用第一個非空白答案，保留其已設定文字。 |
| FR-003 | 自動補答及已儲存的人工補答毋須老師重新輸入、按確認或另行儲存。在無待儲存改判且回合可定案時，老師可直接使用既有的「確認定案」。舊回合缺少已存人工補答及可引用的標準答案時顯示原因，仍可定案。 |
| FR-004 | 收件結束後，授權教師可查看已收到的作答原文及其組別、完整題號、收件順位和自動判分。 |
| FR-005 | 每筆已提交的作答須有一組標為「錯誤」及「正確」的按鈕，恰有一個判定選中。滑鼠與鍵盤均可選擇。選擇只更新對應組別、子題的目前判定，保留自動判分及原答。 |
| FR-006 | 改判及取消或恢復資格時，即時重算審核畫面中受影響子題的自動補答。定案採用已儲存的判定與資格。 |
| FR-007 | 沿用既有審核儲存及定案流程。判定改變時顯示尚未儲存，儲存前不得定案。儲存失敗時顯示可執行的下一步並保留改判草稿。其他分頁已有更新時，沿用逐筆核對後才能儲存的規則。 |
| FR-008 | 定案時，最早送出且符合資格、整個題組皆判為正確的組別得勝。沒有符合條件的組別時顯示「無勝組」。補答不視為任何組別的作答，也不改變收件順位。 |
| FR-009 | 定案後，教師結果及 CSV 以既有補答欄位呈現實際採用的補答，包括保留的人工補答及自動補答。學生公布結果依既有可見範圍顯示。補答不視為勝組答案，試算表回填沿用既有勝組規則。 |
| FR-010 | 只有授權教師可修改目前待審核回合的已收作答。拒絕其他身分、過時版本、未收件項目及已定案回合的改判，並提示原因。學生在公布前的可見範圍沿用現行規則。 |

### 主要實體

- **回合標準答案**　開題時各子題已設定且依序排列的可接受答案。
- **組別作答**　組別與子題對應的已收原文、收件順位、自動判分和教師改判。
- **自動補答**　無具資格組別答對時，由原標準答案提供的該子題補答。
- **定案結果**　回合最終判定、補答與勝組資格結果。

## 成功標準

### 可衡量成果

- **SC-001**　無人送答、全部答錯與部分答對三種情境中，沒有已存人工補答、有標準答案且無具資格組別答對的子題，均只有一筆自動補答。另定案一個含兩個待補答子題的舊回合，確認第一筆已存人工補答逐字保留，第二筆等於第一個非空白標準答案，兩筆均可在教師結果、學生已公布結果及 CSV 讀到。上述情境的補答輸入及另行儲存次數均為零。
- **SC-002**　兩組各送兩個子題的測試中，四筆答案都有各自的「錯誤／正確」按鈕。對同一筆分別以滑鼠和鍵盤改判時，只變更該筆判定，其他三筆及所有原答與收件順位皆維持原值。
- **SC-003**　在同一子題演練「錯誤 → 正確 → 錯誤」時，自動補答依序出現、移除、恢復。另以已失去資格的組別演練一次，改判正確後自動補答仍存在。
- **SC-004**　定案有勝組及無勝組各一次，兩次皆符合最早全對組與資格規則。教師結果、學生已公布結果及 CSV 所引用的補答均與定案時一致。對已定案回合或未獲授權的改判嘗試，成功變更次數為零。

## 假設

- 舊流程中的「補答」是沒有具資格組別答對時提供的參考答案。此次把來源改為老師開題前設定的標準答案。
- 多個標準答案時採第一個非空白答案作為補答，沿用目前公布參考答案的選擇順序。
- 老師仍使用現有的儲存判分及確認定案流程，適用於老師主動改判的情境。
- 本功能接續功能 007 的定案操作區、教師分頁衝突核對及學生倒數。自動補答取代功能 007 對手動補答欄位和定位、填寫、儲存等操作的要求。
