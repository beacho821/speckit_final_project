# 009 驗收紀錄

2026-11-28，Windows、Node.js 24.22.0。

| 驗證 | 結果 |
| --- | --- |
| `npm run typecheck` | 通過前後端型別檢查。 |
| `npm test -- --maxWorkers=2 --testTimeout=15000` | 本機 HTTP 環境下 62 個測試檔、252 個案例通過，失敗 0、略過 0。 |
| `npm run build` | Vite 前端與 TypeScript 後端建置通過。 |
| `node scripts/verify-cooldown-browser.mjs $browserTools` | 兩個學生分頁、教師控制台及投影同場驗證。甲組第一回合得標，第二回合冷卻 8 秒，乙組先送出並得標。教師與投影都從倒數切換為可搶答，甲組冷卻中可讀題，所有答案欄與送出按鈕於期滿後開放。第三回合兩組答對率均為 50%，甲組等 3.45 秒、乙組等 5.75 秒。 |
| `node scripts/verify-teacher-controls.mjs $browserTools` | Edge 在隔離的記憶體教室完成主帳號建立子帳號、子帳號登入、建立教室與組別、匯入 XLSX、採用主要與等義答案、勾選並編修補答、定案及下載。重新開啟下載的 XLSX，確認 C2 與教師輸入一致。 |
| PlantUML | 009 的組件、類別與時序圖已用 PlantUML CLI 產生 PNG，對照擁有者、開題、補答與輸出流程。 |

Edge 已實測下載範例、回匯兩組四人、使用含座號的名字加入。教師移組時，學生停留在即時排名頁，組名更新，重新整理後仍在新組。HTTP 測試確認原組刪除後，該學生仍可替新組提交答案，移除學生則撤銷其分頁憑證。名單測試涵蓋重匯、錯誤列整批取消及名單鎖定。

自動測試另涵蓋跨教師存取、改密撤銷登入、重啟保留教室、同名拒絕移組、無標準答案的人工判分、版本衝突、冷卻截止點、回填衝突與留白後重新辨識小題。

移組回歸另以原組加入碼重現 HTTP 401。修正後，在 Edge 同時開啟使用個人憑證及使用原組加入碼的兩個學生分頁，兩者都會留在即時排名頁並顯示新組。以原碼暫存的分頁重整後可取得個人憑證。HTTP 案例也涵蓋只帶版本號的連續移組、原組刪除後送答及移除成員後的撤權。

教師帳號設定已用 Edge 驗證桌面鍵盤開啟、Escape 關閉及焦點返回。375 × 780 視窗中，教室內可從左下角姓名頭貼開啟設定，關閉後密碼欄位會清空。輸入錯誤的目前密碼後可重試，輸入正確密碼完成變更後，可用新密碼登入並看到原教室。

AI 使用測試替身驗證請求、回應、選用與失敗處理。Edge 已驗證手動新增、匯入題組與入列後整卡編修共用建議視窗，只有空白小題被補上主要及其他可接受答案。元件測試另驗證未勾選、缺題幹、請求期間已填答的小題均會略過，失敗時可保留成功的小題並重試。Google 使用服務替身驗證寫入、留白、重試與讀回。未連線至付費模型或實際 Google 工作表。XLSX 匯入、下載與讀回使用實際活頁簿。瀏覽器重跑方式見 [驗收指南](quickstart.md)。
