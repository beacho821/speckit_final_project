# 實作計畫：課堂線上搶答系統

**日期**　2026-11-16　｜　**Spec Kit 功能**　`001-classroom-buzzer`　｜　**Git 工作分支**　`main`  
**依據**　[已釐清的功能規格](spec.md)與[專題憲章](../../.specify/memory/constitution.md)

## 摘要

老師在同機瀏覽器選取 Google 工作表，核對單題與題組，再依回合開放各組簡答。所有順位由本機 Express 程序在完整收件時決定。React 畫面只接收該角色可見的資料。老師可在回合結束後匯出各組 CSV，並將勝組答案寫回原稿。第一個可演練流程從一位老師、兩組、一個題組開始，再用完整驗收情境檢查公平性與原稿回填。

## 技術背景

| 項目 | 本功能決策 |
| --- | --- |
| 執行與套件管理 | 使用當期正式版 Node.js 與最新穩定版 npm，維持單一根目錄套件與鎖定檔。前後端皆用 TypeScript。 |
| 前端 | Vite、React、Tailwind CSS；教師備課、課中監看、學生作答與結束結果各有對應檢視。 |
| 後端 | Express 最新穩定版，同一程序供應建置後的前端與 HTTP API，只監聽 `127.0.0.1`。驗收使用桌面瀏覽器的多個分頁。 |
| 學習單 | 後端使用 `googleapis` 以服務帳戶執行 Drive 匯出與 Sheets 讀寫。ExcelJS 負責解析 XLSX。課中搶答與結果匯出不需再連 Google。 |
| 狀態與保存 | 程序記憶體保存單一活動。各分頁暫存使用者輸入的憑證與公開活動 ID，後端每次驗證 Basic 憑證、當前名單及活動 ID。重啟清空；寫回的原稿與下載的 CSV 由老師保存。 |
| 測試 | Vitest 執行規則、XLSX 樣本、HTTP 契約、React 組件與整合測試。學生作答組件須實際掛載、填寫與送出，驗證成功確認及缺答後草稿保留。另用教師副本做 Google 實際回填驗收。 |
| 規模與目標 | 一位老師、三個學生組別在同一台電腦連續五回合，所有獲授權的畫面須在 1 秒內顯示變更。無跨機部署、資料庫或自動判分需求。 |

### 已採用套件與版本管理

首次安裝、更新依賴及交付前，核對所有直接依賴與開發依賴的當期最新穩定版，包含新的主版本。以 npm 的 `latest` 標籤為查核起點，排除預覽版。若最新組合有相容性衝突，列出涉及的版本、錯誤及可行選項，交由專題負責人決定。更新後通過型別檢查、Vitest 與建置，再提交對應的 `package.json` 與 `package-lock.json`。操作步驟見[驗收指南](quickstart.md)。

使用者已指定 npm、Vite、React、TypeScript、Tailwind CSS、Node.js、Express、Vitest 與 ExcelJS。下列套件已納入本次實作規劃。之後若有其他直接依賴需求，先提出名稱、用途與必要性。

| 已採用套件 | 用途 |
| --- | --- |
| `react-dom` | 將 React 教師與學生畫面掛載到瀏覽器。 |
| `@tailwindcss/vite` | 在 Vite 建置時編譯 Tailwind CSS。 |
| `googleapis` | 以 Google 官方用戶端處理服務帳戶授權、Drive 匯出 XLSX 與 Sheets 批次回填。 |
| `@types/react`、`@types/react-dom`、`@types/express`、`@types/node` | 開發用型別宣告，依實際版本自帶的型別按需安裝。 |

### 設計圖與實作銜接

- [組件圖](../../diagrams/component.puml)中的兩種畫面由 React 呈現；Express 負責活動與回合、作答驗證與公平順位、依角色提供進度與結果。學習單模組分辨識與寫回兩個步驟；匯出模組使用已結束回合的紀錄。
- [類別圖](../../diagrams/class.puml)中的學習單包含搶答單位與填空。活動持有名單與回合，每筆送出隸屬一組及一回合，每個簡答對應一個填空。活動與來源學習單的數量為 0..1，尚未匯入時不能選題。模型另記匯入時原值與開題時資格，以落實已確認的衝突及公平規則。
- [時序圖](../../diagrams/sequence.puml)用於驗收開題、未勝組先送、曾勝組滿 3 秒送出、結束公布、回填及匯出。開始操作前需登入，首次開題鎖定名單。重開畫面接回目前狀態；這三點依規格釐清紀錄驗收。

### 實作順序與交付條件

1. 建立本機入口、驗證與角色隔離；接通試算表預覽，對照兩份指定格式與一份移位格式（FR-001～FR-003）。
2. 連接回合狀態、同組防重送、公平時鐘與角色專屬更新；演練多人同步及程序重啟（FR-004～FR-008）。
3. 以封存結果產出 CSV，完成來源重辨、整批衝突檢查與寫回，再使用有編輯權的教師副本驗收（FR-009～FR-010）。
4. 各階段納入輸入錯誤與資訊保密測試，最後依 SC-001～SC-005 核對三張圖並交付測試指令及結果（FR-011～FR-012）。
