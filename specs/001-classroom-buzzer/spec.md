# 功能規格：課堂線上搶答系統

**功能目錄**：`specs/001-classroom-buzzer`  
**建立日期**：2026-11-16  
**狀態**：完成規劃與跨文件修正，待實作  
**使用需求**：老師在同一台電腦模擬全班分組搶答，把各題第一順位的簡答寫回原學習單，取代收講義與上台抄答案的流程。

## Clarifications

### Session 2026-11-16

- Q: 若提交前最後一次讀取已發現老師手動修改答案格，回填時如何處理？ → A: 整批暫停，列出衝突題號、目前內容與勝組答案，讓老師處理後重試。
- Q: 第一回合開始後，老師還能在兩個回合之間新增組別嗎？ → A: 第一回合開始時鎖定整堂活動的名單。名單內的組別可稍後開啟畫面參與。
- Q: 如果整個搶答程式在回合中途關閉，重新啟動後需要接續同一堂活動嗎？ → A: 程式仍執行時，重開或重新整理畫面可接回原活動；整個程式重新啟動後開始新活動，已回填的答案與已匯出的 CSV 保留。
- Q: 在本機如何確認老師身分與學生所屬組別？ → A: 老師須以教師密碼進入老師畫面，各組學生須以自己的組別代碼加入。

## 使用情境與測試

### 情境一：老師匯入學習單並確認題目（P1）

老師選取 Google 試算表中的工作表，在開課前核對主題號、子題號、填空數與題組關係。這是避免漏題與寫錯格的第一步。

**獨立驗收**：分別匯入兩份指定範本，再用一份移動過欄列的副本重做。

1. 匯入[單題範本](https://docs.google.com/spreadsheets/d/12uh5xhIx2wXFMy42KU8lN7rLFQ8GDugt9zfAFEvu-1E/edit?gid=1167716485)，預覽須列出第 1 至 6 題，共 6 個填空、6 個單題回合。
2. 匯入[混合範本](https://docs.google.com/spreadsheets/d/1PXXwWiBKJNpPkLRoJLMzZWsAh4Jzn2bThHTeRAiq3Hg/edit?gid=1028924918)，須辨識 4 個主題號、6 個填空。第 1、2 題各含（1）、（2）兩個子題，第 3、4 題各自獨立。
3. 在副本插入標題列、移動「作答」欄，或以可辨識的題號標記連結分散的填空後，題號及所屬題組仍須一致。若同一子題對應兩格，須指出衝突題號與修正方法，保留原先可用的匯入結果。

### 情境二：全班同步搶答，老師掌握進度（P1）

老師選擇一個單題或題組開啟回合。各組依紙本或原學習單閱讀題目，在自己的學生畫面填寫簡答；老師可即時看到哪些組已送出及已收到的答案。

**獨立驗收**：在同一台電腦開啟老師、甲組與乙組三個獨立畫面，以一個含兩個子題的回合演練。

1. 老師以正確的教師密碼進入老師畫面；甲、乙組各以自己的組別代碼進入對應的學生畫面。準備時各畫面顯示相同題號與階段。老師開啟後，甲組填完兩格並一次送出；老師看到甲組的兩個答案與暫列順位，乙組只看到自己的狀態。
2. 乙組若有一格只有空白，須看到缺答的子題號，保留已填內容；老師端仍顯示乙組未送出。乙組補齊後取得同一筆送出的順位，適用於整個題組。
3. 老師結束後，所有畫面同步顯示最終結果。若送出與結束幾乎同時發生，以活動接受操作的先後為準；先結束則拒收，已接受的答案仍計入。
4. 丙組已列入首回合名單，第二回合才開啟學生畫面，仍可代表丙組參與；第一回合的 CSV 列出丙組為「未送出」。若老師在兩回合之間嘗試新增丁組，須提示名單已鎖定、下次活動可在開題前加入，且名單與既有結果均不變。
5. 回合進行中另開同組學生畫面，須直接看到目前階段及本組是否已送出。再次送出不得更改答案或新增順位。
6. 甲組送出後，老師與甲組分別重新整理或關閉再開啟畫面。只要搶答程式仍在執行，老師須看到原回合的階段、答案與順位，甲組須看到本組已收件且無法重送。
7. 首回合結束後，老師關閉分頁並重新登入。畫面列出剩餘可選單位與完整題號，老師可直接選取第二個單位並開題，全程無須重新匯入。

### 情境三：未得分組先有送出機會（P1）

同一堂活動有多個回合時，已成功的組別仍可繼續作答，尚未成功的組別享有短暫的優先送出時間。

**獨立驗收**：安排甲組已贏過上一回合、乙組尚未贏過，再開一個新回合。

1. 回合開始時兩組都能填答。甲組在第 2 秒嘗試送出，畫面須說明開放時間並保留答案；若乙組此時有效送出，即取得第一順位。甲組在第 3 秒起可送出。
2. 若乙組尚未送出，甲組在第 3 秒先有效送出，則甲組獲勝。上一回合的成績不會在本回合結束後改寫其順位。
3. 第一回合所有組都可立即送出；所有參與組都曾勝出時也同樣開放。近乎同時收到的兩份有效送出須得到不同且穩定的順位。

### 情境四：老師回填原學習單並匯出活動結果（P2）

老師把已結束回合的第一順位答案寫回對應填空，並下載全班明細，省去逐題抄寫與整理順位。

**獨立驗收**：以已結束的混合範本活動、已知的各組答案與一份可編輯的來源工作表，比對寫回與匯出結果。

1. 題組第一順位為甲組時，第（1）、（2）格各寫入甲組對應子題的原文。移動作答欄後再寫回，仍須命中同一題；其他組答案只出現在結果明細。
2. 有一題無人送出時，顯示「無人搶答」，保留該格原值。若回填前移除了目標格、對應不唯一或來源無編輯權，須指出原因及修正方式，該次寫回不得留下部分變更。成功後重試同一份結果，內容須一致。
3. 匯出已結束回合時，每個填空、每個組別各有一列。以試算表開啟 CSV，含逗號、雙引號或換行的答案仍在同一欄；未送出組保留一列並標示狀態。
4. 第 2 題匯入時空白，老師後來填入「中央處理器」，勝組答案為「CPU」。回填時須顯示第 2 題與這兩個值，整批零寫入。老師將該格還原為匯入時的內容，或改成「CPU」後重試，若其他目標都沒有衝突，整批回填成功。
5. 若提交後讀回的答案與預期不同，顯示「寫回結果待確認」及受影響題號，保留現況供老師核對。若外部編輯發生在最後讀取與提交之間，又被同批寫入取代，系統無法由讀回結果辨識該次編輯。寫回畫面須在提交前提示共編者暫停修改。

### 邊界情況

- 空白或重複組名、空白學習單、無法存取的來源、重複題號或引用不存在題號的題組，均須指出問題與修正方式；錯誤輸入不得取代有效資料。
- 尚無組別或未選出題目時，老師不得開啟回合。首回合開始後不能新增、刪除或更名組別。回合進行中不得修改題組或重複開啟；已結束的回合不能再收件。
- 學生在準備或進行中直接嘗試查看他組結果、匯出或使用老師操作時也須被拒絕，畫面不得透露他組是否送出。
- 尚無已結束回合時，回填與匯出須提示先結束一回合。已有結果時，僅處理已結束回合，保留活動中尚未開放的題目。
- 教師密碼錯誤或組別代碼無效時，須提示重新輸入對應憑證，且不得顯示活動資料或變更收件紀錄。只提供組名不能加入；持甲組代碼另開畫面，只能進入甲組。教師密碼不得與任何組別代碼相同；設定碰撞時拒絕啟動，只指出需修正的環境變數。
- 若整個程式在回合中途關閉，重新啟動後須進入新活動的準備階段，名單、回合、已收答案、順位與勝出紀錄皆為空。先前已寫回的工作表與已下載的 CSV 須維持原內容。

## 需求

### 功能需求

| 編號 | 可驗收的行為 |
| --- | --- |
| FR-001 | 同一台電腦可同時開啟一位老師及多個獨立學生組別畫面。老師可在首回合開啟前編輯不重複的組名清單，首回合開始即鎖定至整堂活動結束。公平順位與各回合 CSV 均採用這份名單。老師必須通過教師密碼驗證才能使用老師畫面及操作。教師密碼與各組代碼須彼此不同。每組的有效代碼須唯一對應名單中的一組；學生可稍後以自己的組別代碼加入，通過驗證的畫面僅能代表該組。 |
| FR-002 | 老師可匯入指定的 Google 工作表。系統依題號、子題、作答欄標題或約定標記動態辨識填空及題組；匯入和寫回均不得依賴固定列、欄、儲存格位址或範本名稱。 |
| FR-003 | 預覽須列出與原稿一致的題號、子題號、題組歸屬及填空總數。活動只顯示題號供對照，每格接受簡答。標記式學習單可把同一題組的不同題號編在一起；每個填空只能屬於一個送出單位。 |
| FR-004 | 老師每回合選一個尚未使用的單題或題組，依序切換「準備、進行中、結束」。同時只可有一個進行中的回合。結束後可準備下一回合，已結束的結果可再查看。程式仍執行時，新開、重開或重新整理畫面皆須能接回同一活動。畫面須先確認有效的教師或組別身分，再顯示該身分可見的階段與收件狀態。老師重新登入須能取得尚未使用的單位與完整題號，直接開啟下一題。整個程式重新啟動即開始新活動。 |
| FR-005 | 每組每回合只接受首次有效送出。每個所選填空都須含非空白文字，題組全部通過才一併收件。拒收時須保留草稿並指出缺答、時機或重複送出的原因。 |
| FR-006 | 於開題時按本活動先前已結束回合的勝出紀錄決定送出資格。若有未勝組，曾勝組開題滿 3 秒才能送出；未勝組可立即送出。所有組都曾勝出時，全部立即開放。畫面須在送出前說明本組規則與剩餘等待時間。 |
| FR-007 | 只對有效送出依活動實際收件先後給予唯一連續順位。第一順位贏得本回合每一題；題組各題共用順位。即使顯示時間相同也維持收件先後，結束後順位固定。無有效送出即無勝組。 |
| FR-008 | 老師在進行中可即時檢視各組是否送出、已送答案、順位及暫列第一組。學生只可查看本組作答及收件確認；包含本組順位在內，會透露他組進度的資訊一律在結束後才公布。所有組結束後可查看各題、各組答案與順位。 |
| FR-009 | 老師可將已結束回合的勝組答案逐格寫回當初匯入的來源工作表。須核對目前的題號與填空對應，只變更有勝組的答案內容，保留題目敘述、版面、格式及其他儲存格。提交前最後一次讀取須比對所有目標格：當時內容若與匯入時內容及勝組答案皆不同，整批暫停，列出每個衝突題號、目前內容與勝組答案，提示老師處理後重試。已等於勝組答案的格子視為已回填。簡答即使以等號開頭也須作為文字寫回。提交後讀回題號、值與必要識別備註，全數相符才回報成功；不符或無法核對時標示待確認，不自動覆寫或回滾。 |
| FR-010 | 老師可將本次活動已結束回合匯出為 CSV。欄名依序為「題號、組別、答案、搶答順位、作答狀態」；題組以完整子題號區分。未送出的答案與順位留空，狀態為「未送出」；成功收件標示「已送出」。 |
| FR-011 | 所有操作須驗證角色、階段及適用的輸入條件。訊息以正體中文指出問題與下一步，拒絕的操作不得改變既有資料。老師與各組用輸入的憑證逐次對照後端環境變數驗證，不另發課堂存取權杖。教師密碼、各組代碼及其他機敏值只可由環境變數提供，程式碼、日誌、錯誤訊息及測試輸出均不得出現真值。 |
| FR-012 | 每項功能須有至少一個可重跑的正常案例與一個邊界案例；交付時列出實際測試指令、結果與未通過原因。拒收類案例須同步核對訊息與資料未變更。 |

### 主要實體

- **學習單與填空**：記錄來源工作表、可供辨識的題號及選填的子題號。完整題號唯一對應一個原稿填空，並保留匯入當時的答案格內容，供回填時比對。
- **搶答單位**：單題含一個填空，題組含多個填空。兩者皆占一個回合。
- **活動與回合**：一堂活動包含組別名單與多個回合。每回合記錄搶答單位、階段、開放時點及勝組。
- **組別與送出紀錄**：同一組別代碼加入的畫面代表同一組，共用該組每回合唯一的有效送出紀錄，保留各題簡答與唯一順位。曾否勝出以同一活動已結束回合的第一順位判定。

## 成功標準

### 可衡量的成果

- **SC-001**：用單題版、混合版與一份移動欄列或填空的不同版面逐一比對，三份的題號、子題、填空數與題組歸屬均須 100% 符合預先列出的對照表。
- **SC-002**：在同一台電腦以一位老師及三組學生操作，連續五回合中，每次階段變更與有效送出後，所有有權看到該變更的畫面均於 1 秒內自動更新。結束前，三組學生畫面揭露他組答案、狀態或順位的次數為零。
- **SC-003**：重演首次開題、曾勝組提前送出、恰滿 3 秒、全組皆曾勝出、近乎同時送出、無人送出六種情境。每次公布的勝組與完整順位均須符合事先推算的結果。
- **SC-004**：同一堂活動至少含一個題組、一個單題及一個無人送出的回合。在回填過程無外部共編的驗收副本上，全部有勝組的填空均對應正確，其他儲存格內容與格式零變動；CSV 的列數等於已結束回合填空數乘以組數，答案與順位逐列相符。
- **SC-005**：一位老師使用畫面提示完成匯入、開題、結束、原稿回填及 CSV 匯出，全程無須手動查找儲存格位址或重新抄寫答案。

## 假設與範圍

- 本機模擬涵蓋一位老師與多個組別，不要求其他設備連入。讀取或更新 Google 試算表時可連網；老師有來源讀取權，回填驗收使用具編輯權的原稿或教師副本。
- 可沿用兩份範本的「題號／作答」表頭及子題編號，也可在另製範本中使用穩定標記。例如在填空標示「答案：甲組題／5」與「答案：甲組題／8」，代表題號 5、8 同屬名為「甲組題」的題組。標記辨識須能在移動填空後保有關聯；回填後也須保留可再次辨識的題目身分。
- 「成功」指最早符合資格且完整送出的組別。教師仍可檢視簡答內容；本次範圍不含自動判分。公平機制採固定 3 秒優先時段，依本堂活動累計是否勝出；新活動重新計算。
- 規劃階段以[組件圖](../../diagrams/component.puml)、[類別圖](../../diagrams/class.puml)及[時序圖](../../diagrams/sequence.puml)為設計依據。實作完成後須比對圖中的角色權限、回合關係與送出順序。
