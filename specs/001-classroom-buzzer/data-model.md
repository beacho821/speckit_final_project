# 資料模型與回合規則

此模型細化[類別圖](../../diagrams/class.puml)。識別碼均限本機活動使用。Google 原稿資訊只供後端及獲授權的老師操作。

| 實體 | 欄位及關係 | 驗證或不變條件 |
| --- | --- | --- |
| 活動 | 公開活動識別碼、可選的來源學習單（0..1）、組別集合、是否已鎖定名單、回合歷程、目前回合 | 程序啟動時建立空活動。另開畫面不會重建活動。 |
| 學習單 | 文件 ID、Google 分頁 ID、顯示名稱、依原稿順序排列的搶答單位 | 匯入整份驗證成功才替換預覽。首回合前可以重匯；已有回合紀錄時保留其原始來源與題目身分。 |
| 搶答單位 | 單位 ID、單題或題組、依原稿順序排列的一或多個填空 ID | 每個填空只屬於一個單位。同堂活動每單位至多開題一次。 |
| 填空 | 完整題號（例如 1（2））、主題號、可選子題號、辨識方式、原稿輸入值及型別 | 完整題號與同單位內子題均須唯一。儲存的題號關係用於再辨識；匯入時列欄只供錯誤提示。 |
| 組別 | 內部 ID、顯示名、環境變數中對應的代碼項目識別 | 名稱去除首尾空白後不得空白或重複。授權代碼唯一且與教師密碼不同。名單可於首回合前新增、刪除、更名；更名不改變代碼對應的組別 ID。 |
| 分頁登入狀態 | 本次活動 ID、驗證所得角色及學生組別 ID | 分頁只在記憶體暫存使用者輸入的憑證。後端每次以環境設定與當前名單重驗，移除組別即撤權。程序重啟時更換公開活動 ID，拒絕舊活動請求並要求重新登入。 |
| 回合 | 回合 ID、單位 ID、階段、開始時刻、各組開放送出的時刻、依接受先後排列的送出紀錄 | 每次變更須比對目前回合 ID 與階段。首回合開啟時鎖名單，後續回合沿用同一份名單。 |
| 送出與簡答 | 回合 ID、組別 ID、正整數順位、各填空 ID 與答案原文 | 每回合每組至多一筆。提交題號集合須完全等於本單位填空集合，無漏題、重複、多餘或純空白。通過檢查後保存未裁切的原文。 |

## 狀態轉換

| 原狀態 | 操作 | 成功後 | 拒絕範例 |
| --- | --- | --- | --- |
| 活動準備／上一回合結束 | 老師選單題或題組 | 新回合「準備」，所有人看到同一組題號 | 來源未匯入、選已用單位、另一回合仍進行中 |
| 回合準備 | 老師開啟 | 「進行中」，凍結本回合資格及開放時間 | 名單為空、回合 ID 過期、重複開啟 |
| 進行中 | 學生送出 | 仍為「進行中」，新增一筆完整收件 | 等待未滿、組別未驗證、題組缺答、已收過該組 |
| 進行中 | 老師結束 | 「結束」，封存結果並公布 | 尚未開啟、重複結束 |
| 任意 | 程序重新啟動 | 新活動準備，沒有名單、回合或勝組 | 舊頁操作須重新登入，不得重播到新活動 |

尚在準備的選題可由老師改選未用單位，舊準備回合失效；開啟後即固定題組。匯入為非同步操作；發布預覽前要再次驗證活動、來源及選題狀態，已被更新的舊請求不得覆蓋後來的選擇或已開啟的回合。更換來源只允許在尚無已開啟回合時進行，成功後清除準備中的舊選題。重開已用單位會破壞歷程中題號與回填的一致性。

## 時間與收件

開題時從已結束回合的第一順位推導曾勝組。若名單內仍有未勝組，曾勝組的開放時間為開題後 3,000 毫秒，其他組於開題即有資格；若所有組均曾勝出，一律立即開放。比較採後端單調時鐘的「大於或等於」，重新整理或手動改用戶端時鐘均不改變資格。

已完整收到並通過驗證的請求按後端處理先後收件。檢查是否結束、檢查同組重送、編號與新增紀錄在同一同步步驟內完成；結束操作使用同一序列。順位等於該回合已接受數加一。第一筆取得整個單位內各填空的勝出資格，無人送出時勝組為空值。逾時重送先查本組收件狀態，不能覆蓋第一筆答案。

## 對外可見性

教師可見依原稿順序排列的尚未使用單位（ID 與完整題號）、整份名單、每組收件、答案、順位與歷次結果。學生在本回合結束前只可見階段、題號、自身送出資格與本組收件狀態；本組的送出確認也不帶順位。已結束回合才提供完整各組明細。用戶端草稿與後端正式收件分開，拒收或更新畫面資料時保留該回合草稿；重新開啟分頁須重新驗證，已收資料仍保留。
