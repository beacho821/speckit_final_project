# 本機啟動與驗收指南

本指南記錄本機啟動方式、可重跑驗收案例及目前實際驗證結果。最新驗證紀錄見文件末尾。

## 準備環境

1. 使用 Node.js 22.12 或更新版本及 npm。在專案根目錄以 `node --version`、`npm --version` 記錄實際版本，依鎖定檔安裝套件。
2. 建立可編輯的單題與混合範本副本，再建立一份移動表頭、作答欄與分散填空的變形副本。單題和題組版的來源連結在[功能規格](spec.md)。實際 Google 驗收需啟用 Drive 與 Sheets API，將副本分享給該次使用的 Google 服務帳戶並給予編輯權。
3. 將 `.env.example` 複製為 `.env`，設定教師密碼。`.env` 已加入 Git 忽略清單。若使用 Google 匯入或回填，再設定服務帳戶 JSON；加入碼由老師在活動中建立組別時產生，不必預先設定學生代碼。

| 環境變數 | 內容及用途 |
| --- | --- |
| TEACHER_PASSWORD | 非空的教師登入密碼。 |
| GOOGLE_SERVICE_ACCOUNT_JSON | 選填；服務帳戶 JSON 檔案路徑，可使用相對於專案根目錄的路徑。僅使用本機 XLSX 時不需要。 |
| PORT | 選填；API 連接埠，預設 3000，須為 1 至 65535 的整數。 |

教師密碼缺少或空白時，啟動訊息只指出變數與設定方式，不回顯輸入值。Google 授權須能讀取試算表；回填驗收另需編輯權限。自動化案例使用測試替身與執行期虛構憑證。

## 套件更新與交付查核

- 初次建置時，對每個已確認的直接依賴（含開發依賴）查 `npm view <套件名稱> dist-tags --json`，採用最新穩定版。若 `latest` 指向預覽版，查 `npm view <套件名稱> versions --json` 核對正式發行版本。
- 已有鎖定檔時先執行 `npm ci`，再執行 `npm outdated --include=dev`，比較 Current 與 Latest，包含跨主版本的差異。以 `npm install <套件名稱>@<確認版本>` 更新執行依賴；開發依賴加上 `-D`。已採用套件以[實作計畫](plan.md)為準。清單以外的直接依賴須先提出名稱、用途與必要性。
- 更新後重跑下列型別檢查、測試與建置，再複查版本並一併提交 npm 套件清單與鎖定檔（`package.json`、`package-lock.json`）。遇到版本衝突時回報套件名稱、版本與測試結果。[npm 版本檢查文件](https://docs.npmjs.com/cli/commands/npm-outdated/)

## 指令

```sh
npm ci
npm run typecheck
npm test
npm run build
npm start
```

`npm test` 須單次執行 Vitest 並回傳成敗。需要重跑契約案例時可用 `npm exec -- vitest run tests/contract`。建置後開啟 `http://127.0.0.1:3000`，一個教師畫面與三個獨立學生畫面共用同一個 Express 程序。學習單可在瀏覽器外查看題目內容，搶答畫面只顯示題號。

React 組件案例可單獨執行 `npm exec -- vitest run tests/components/StudentRound.test.tsx`。以實際輸入與送出事件檢查完整答案顯示收件確認；缺一格時顯示該題號，其他欄位維持原文且不顯示已收件。

## 課堂演練

1. 教師登入後加入甲、乙、丙三組。匯入單題版，確認 6 個單位；在首回合前改匯混合版，確認 4 個單位、6 個填空。以無效格式重匯，原預覽應仍可使用。用各組代碼登入，刻意用錯誤代碼及學生身分的教師請求，兩者都不得看到全班資料。
2. 開啟題組 1。甲組一次送出兩答取得第一順位。乙組先留一格空白，須看見確切子題且保留另一格，再補齊送出。老師即時看到兩組紀錄，丙組看不到他組狀態。結束後所有人看到甲、乙的順位與丙未送出。
3. 關閉教師分頁並重新登入，無須重新匯入，即可從未使用的清單選取並開啟題組 2。學生畫面不得取得這份教師清單。甲組填答但未滿 3 秒不可送出；此時由乙組先送可取得第一。另一演練讓甲組在滿 3 秒時先送，應由甲組獲勝。重送、同組另開分頁或使用前回合 ID 都不能新增順位。這些臨界值用 Vitest 可控時鐘重現。
4. 開啟並結束單題 3 而無人作答。此時已有五個已結束的填空與三組，CSV 含表頭及 **15 筆**明細。第 4 題尚未開放，不能出現在輸出。用 CSV 讀取器比對答案中逗號、引號、換行與原文。
5. 在教師副本移動作答欄，手動改寫其中一個目標格，再按回填。預期顯示衝突的完整題號、現值與勝組答案，整批零變更。還原後重試，核對四格勝組原文、第 3 題仍空白、第 4 題未改；再回填一次，結果應一致。另以 Google 測試替身模擬批次已套用、讀回時有一格遭外部改值，須取得「寫回結果待確認」及差異題號，寫入批次呼叫總數仍為一。
6. 重新整理後以同組憑證接回，確認同一回合與收件。關閉整個後端再啟動，舊登入失效，新活動的名單與勝組紀錄為空；已寫回的副本與先前下載的 CSV 仍能開啟。
7. 另開新活動，以 6 單題版完成至少五回合，保持教師與三組畫面連線。逐次記錄從操作被接受至各授權畫面呈現變更的時間，最慢不得超過 1 秒。對照[時序圖](../../diagrams/sequence.puml)，檢查結束前洩露的他組事件數為零。

## Vitest 正常與邊界案例

| 規格 | 正常案例 | 邊界案例與預期 |
| --- | --- | --- |
| FR-001 | 教師與三組同時登入並保有各自權限 | 設定中學生代碼與教師密碼相同時拒絕啟動且不揭露真值。錯誤密碼、無效或重複代碼拒絕；首回合後名單更動零生效。 |
| FR-002、FR-003 | 以 ExcelJS 載入三種 XLSX，逐項比對既定題號、單位與實際填空 | 模擬改欄、合併、缺標或重複標記；移位仍成功，歧義整份拒絕並保留先前預覽。 |
| FR-004 | 所有組依序看到準備、進行中、結束；重連可取現況 | 無名單開題、重複開題、舊回合送出被拒；程序重啟為新活動。 |
| FR-005 | 題組完整收件且原文相符 | 純空白、漏答、多答、重複題號、同組平行送兩次；拒收不消耗順位。 |
| FR-006、FR-007 | 未勝組先送或全組皆勝時先送，勝者取得所有所屬填空 | 2,999 毫秒拒收、3,000 毫秒可收；同時送出無並列，與結束競爭依接受先後，無人送出無勝組。 |
| FR-008 | 老師即時看全班，學生只見本組，結束後公布 | 檢查學生 HTTP 回應、可見版本及未返回的長輪詢，不能以直接查詢或事件次數推知他組送出。 |
| FR-009 | 勝組各欄正確回填，等號開頭存字串，格式、既有備註與其他儲存格保留 | 手動改值、目標移除、無權限、提交回應遺失。分別檢查提交前衝突零寫入，以及提交後讀回不符或回應遺失時標示待確認；重試必須先核對原稿。 |
| FR-010 | 各填空乘名單組數等於匯出筆數，排序與封存結果一致 | 含換行／雙引號的答案可完整讀回，無勝組的空欄及未結束回合處理正確。 |
| FR-011、FR-012 | 各入口通過合法輸入，交付列出正常與邊界測試指令和結果 | 拒絕時核對中文修正方式與資料不變；以執行期假憑證檢查日誌、錯誤與客戶端建置內容。 |
