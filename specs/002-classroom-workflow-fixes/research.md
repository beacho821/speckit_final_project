# 研究紀錄：開課設定、學習單匯入與學生加入流程修正

**日期**：2026-11-17\
**依據**：[規格](spec.md)、[組件圖](../../diagrams/002-component.puml)、[類別圖](../../diagrams/002-class.puml)、[時序圖](../../diagrams/002-sequence.puml)。

## 研究方式與基準

依規劃技能分派兩個唯讀研究代理，分別核對身分／名單／重連與 XLSX／合併儲存格／原子發布；主流程研究開發啟動與官方文件，再整合決策。沒有修改應用程式或新增套件。

- 已讀實際 `package.json`、設定、前後端、共用型別、既有 001 契約及下載快照。現有 TypeScript、React、Vite、Express、ExcelJS 足以完成本次需求。
- `npm test` 在一般沙箱因 `listen EPERM 127.0.0.1` 造成六組 HTTP 測試無法啟動；允許本機連接埠後重跑，15 個檔案、43 個案例全部通過。
- `npm run typecheck` 通過。這是既有版本的基準，不代表 002 功能已實作。

## R-001：單一開發入口與環境設定

**決策**：新增 `scripts/dev.mjs`，使用現有 TypeScript 編譯器先編譯後端，再匯入編譯後的共用啟動模組，於同一程序啟動 Express 及 Vite JavaScript API。`npm run dev` 只需這個入口。前端保有 Vite 熱更新；後端程式修改後手動重啟整個開發入口，並依規格開始新活動。

**理由**：目前 `dev` 只有 Vite，後端才會呼叫 `process.loadEnvFile()`；Vite 的專案根又設為 `frontend`，不能把問題簡化為增加前端公開環境變數。共用 `bootstrap.ts` 讓開發及正式入口使用同一設定驗證與啟動順序，不新增程序監督或 TypeScript 執行套件。

根目錄 `.env` 用 Node 原生載入；保留已存在的環境值，只忽略檔案不存在的 `ENOENT`，其他讀檔錯誤以正體中文報告且不輸出內容。移除 `GROUP_CODES_JSON` 的讀取與啟動要求。驗證完成且 API 監聽成功後才啟動 Vite，代理目標使用實際驗證後的 `PORT`；失敗或停止時關閉兩個服務。入口將 cwd 固定為由自身檔案位置解析出的專案根；正式 `npm start` 亦從套件根執行。Vite `envDir` 指向專案根，僅保留預設 `VITE_` 公開前綴，教師密碼及雲端金鑰禁止使用該前綴。

**替代方案**：雙終端仍不符合需求；新增 `tsx` 與程序監督套件會增加目前不必要的依賴；直接以 Node 執行來源 TypeScript 在最低支援版本及 `.js` 匯入解析上不如沿用現有編譯流程可靠。

**依據**：[Node 環境變數工具](https://nodejs.org/api/environment_variables.html#programmatic-apis)、[process.loadEnvFile](https://nodejs.org/api/process.html#processloadenvfilepath)、[Vite createServer](https://vite.dev/guide/api-javascript.html#createserver)、[Vite 環境變數公開規則](https://vite.dev/guide/env-and-mode)。這些文件支持 API 能力；上述啟動順序是本專案的設計決策。

## R-002：組別、加入碼與成員分開存放

**決策**：保留公開 `GroupSummary {id,name}`，在活動內另存 `joinCodes`、`usedJoinCodes` 與 `members`。組別以獨立新增、更名、刪除操作取代全量 `PUT /roster`。加入碼以 `node:crypto.randomInt` 從 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` 產生 8 字碼，檢查本活動已用過的碼及教師密碼；碰撞重新產生，刪除的碼不回收。

**理由**：目前回合會複製公開組別名單。秘密若混入公開組別，很容易由回合、學生快照或結果洩漏。獨立 CRUD 也避免老師的舊表單覆蓋其他分頁剛新增的組別或成員。所有驗證與修改在不含 `await` 的同步區段完成。

**替代方案**：把秘密附在每個公開組別再逐一刪欄位容易漏；全量更新需要額外版本衝突處理；資料庫與跨程序同步不符合活動重啟即清空的範圍。

## R-003：沿用 Basic，學生登入補上名稱

**決策**：教師仍用 `Basic teacher:密碼`；學生用 `Basic student:加入碼` 搭配登入 JSON `{name}`。驗證碼與名稱後，以 `(activityId,groupId,trimmedName)` 同步取得或建立成員。後續請求附 `X-Member-Id`，每次仍核對活動、有效組碼及該成員所屬組；成員 ID 本身不授權。

**理由**：滿足加入碼及名稱必填，不新增帳號或權杖系統；正體中文名稱放在 JSON，避免直接塞入 HTTP 標頭。同組同名重連沿用原紀錄，名稱保留至刪組或活動重啟。

**替代方案**：Bearer 權杖、Cookie 工作階段會新增撤銷與多分頁角色隔離需求；名稱作密碼或允許成員 ID 單獨授權都違反規格。

## R-004：分頁恢復與斷線重連

**決策**：學生成功登入後，將活動 ID、加入碼、名稱及成員 ID 放入該分頁的 `sessionStorage`；重新整理先重新呼叫登入驗證，且必須帶原活動 ID。不能以暫存值直接顯示活動。登出、撤權或活動過期即清除；教師密碼只留記憶體，教師重新登入後恢復同活動資料。不使用跨分頁的 `localStorage`。

長輪詢沿用 20 秒等待、100 毫秒檢查與單一在途請求。網路錯誤後清除 `after`，800 毫秒內重試完整快照；瀏覽器 `online` 事件可立即觸發重連。成功驗證後立即取得最新狀態，不再等待舊版號逾時。只自動重試讀取／身分恢復，絕不自動重送答案或名單修改。教師快照增加 `rosterVersion`，變動後重讀教師專用名單。

**理由**：目前登入只在 React state，無法通過重新整理驗收；現有輪詢錯誤後保留舊 `after`，可能再次等待 20 秒。同組首次有效送答仍由既有同步收件判定。

**替代方案**：只留記憶體無法符合學生重新整理；共享本機儲存會混淆多分頁角色；在線心跳不是「曾加入名單」所需功能。

**相容性及治理**：002 取代 001 契約中「登入資料僅留分頁記憶體」的限制；憲章已於 2026-11-17 修訂為 2.0.0，正式允許活動產生加入碼及學生本人分頁的限定暫存。伺服器碼表只存活動記憶體、授權教師可查看；學生只將本組碼及恢復資料暫存於本人 sessionStorage，得知撤權／過期或登出即清除。教師密碼不存 Web Storage，仍禁止在網址、日誌、版本化檔案或他組回應洩漏碼；不擴充為跨瀏覽器登入。

**依據**：[HTML Standard 的 sessionStorage](https://html.spec.whatwg.org/multipage/webstorage.html#the-sessionstorage-attribute) 定義分頁工作階段儲存；重新驗證與撤權策略為本專案決策。儲存不可用時仍可在記憶體中登入與重連，但須提示重新整理後需重登；正式重新整理驗收使用允許分頁儲存的瀏覽器。

## R-005：本機 XLSX 以 raw 二進位上傳

**決策**：新增教師專用 `POST /api/worksheet/import/xlsx`，以路由限定的 `express.raw` 接收檔案，byte limit 為 10,485,760，`inflate:false`；沿用全域 JSON 100 KB 上限。檔名經 URI 編碼放在 `X-File-Name`，只供副檔名驗證及顯示，不用作磁碟路徑。先檢查教師、活動及鎖定，再接收檔案。

**理由**：`fetch` 可直接傳 File，既有 ExcelJS 可載入 Buffer，不需 Base64、multipart 套件、伺服器暫存檔或前端解析器。大小檢查涵蓋串流實際讀取，不只信任 Content-Length。

多工作表先回候選且不發布；瀏覽器保留 File，選妥後重新上傳同一檔並附檔案內的 `sheetId`。單張可直接發布。候選 ID 不假設由 1 開始。選檔對話框取消不發請求；處理中不提供取消／切換來源入口，避免把中止 HTTP 誤認為已回滾伺服器提交。

**替代方案**：伺服器草稿上傳會新增容量與到期回收；前端解析會增加下載體積及重複後端驗證；multipart 在本次單檔流程沒有必要收益。

**依據**：[Express raw 官方契約](https://expressjs.com/en/5x/api/express/#express.raw) 支援 Buffer、數值 byte limit 及壓縮選項；路由與錯誤分類見本功能契約。

## R-006：共用辨識器與合併主格

**決策**：本機／Google 共用 `identifyWorksheet`。表頭、標記及答案位置先正規化到合併主格，以主格位址去重；垂直合併主題號的各列仍按不同子題辨識。填空座標與原值都保存主格，不能只在讀文字時使用主格。改以有內容列／格及必要合併關係掃描，避免擴展整張稀疏矩形。

**理由**：研究代理以已下載單題檔實測，第 4 列 G、H 都讀到「作答」；現行迴圈最後選 H，且 `H5.master` 為 G5，保存的 column 卻是 H。既有合成 fixture 缺少橫向合併表頭與答案，43 個通過案例沒有涵蓋這個問題。兩份原始下載檔必須直接進入回歸。

取文字時區分文字、數字、richText 及 hyperlink 顯示文字。辨識所需的表頭、題號、子題或標記若只能靠公式結果取得，拒絕並提示貼上值後重試；其他不參與辨識的公式不執行。答案格原公式原值可保留，供既有 Google 回填比對。

**替代方案**：固定 B/G 欄無法通過移動欄列；公式計算引擎超出需求；更換整套試算表解析器無必要。

**依據**：[ExcelJS 4.4.0 官方文件](https://raw.githubusercontent.com/exceljs/exceljs/v4.4.0/README.md) 說明合併格及公式結果限制；主格位置缺陷來自本專案實測。

## R-007：來源聯集與原子發布

**決策**：`WorksheetSource` 改為 `kind:'google'|'xlsx'` 判別聯集；只有 Google 分支有 `documentId`。本機來源在任何 Google I/O 或注入回填服務前即回 `WRITEBACK_NOT_SUPPORTED`。CSV 欄位保持既有格式。

兩種來源共用目前的 `importGeneration` 與 `publishImportedWorksheet()`：驗證活動及未鎖定、取得操作序號、完整讀取與辨識，再於同步提交前檢查活動、序號、鎖定及請求是否已失效。成功才換學習單並清除準備回合，保留組別、碼與成員；候選、取消選檔、驗證未通過或發布前被拒絕均不發布。若匯入期間先開題或已有較新操作，本次操作不得覆蓋活動，也不回滾其他分頁已發布的資料。

傳輸中斷或回應遺失不等於伺服器已拒絕。前端須顯示「匯入結果待確認」，不自動重送、宣告成功或宣告零寫入，立即以不帶 after 的教師快照恢復目前來源及選題；無法取得快照時保持待確認並停用再匯入／開題，取得後再恢復可用操作。
上述保留待確認適用暫時連線失敗；若收到撤權或活動過期結果，仍須清登入並返回加入流程，不重送原操作。

**理由**：既有發布函式已實作大部分必要保護，補齊共用來源及前端選題重置即可。前端另以請求序號避免舊回應覆蓋較新畫面，教師完整快照含來源與題目摘要供重新登入還原。

**替代方案**：解析過程逐步修改活動會留下部分狀態；兩來源各自維護計數器會允許跨來源晚回應覆蓋；把原始 Buffer 常駐活動會保留不需要的資料。

## 結論

所有技術待決事項已解決；兩項使用者澄清均有直接設計對應。沒有新增業務範圍或套件。下一階段依上述決策建立資料模型、HTTP／匯入／介面與啟動契約及快速驗收指南。
