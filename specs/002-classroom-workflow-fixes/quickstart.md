# 快速驗收指南

**用途**：可重跑的功能驗收操作。實際執行結果及未執行範圍見 [實作驗證紀錄](validation-results.md)。

## 前置條件與啟動

需要 Node.js 22.12 以上、npm、可使用 sessionStorage 的瀏覽器，以及允許本機連接埠的執行環境。Google 回歸另外需要可讀寫的測試副本及本機服務帳戶設定，不能用範例原稿進行寫入驗收。

從專案根執行：

```sh
npm ci
cp -n .env.example .env
npm run dev
```

啟動前先以編輯器在 `.env` 設定自己的 `TEACHER_PASSWORD`。移除 `GROUP_CODES_JSON`，Google 設定可留空；不把實際密碼貼入命令列或測試輸出。`cp -n` 用於避免覆蓋既有設定，不需反覆複製。開啟終端列出的前端位址；單一指令必須同時使前端與 API 可用。關閉使用 Ctrl+C，後端或環境設定修改後重新執行會開始新活動。

## 可重跑檢查指令

```sh
npm run typecheck
npm test
npm run build
```

以下為已建立的聚焦測試：

```sh
npm test -- tests/unit/config.test.ts tests/integration/dev-startup.test.ts

npm test -- tests/unit/xlsx-source.test.ts tests/unit/worksheet-parser.test.ts tests/contract/xlsx-import.test.ts tests/integration/import-preview.test.ts
npm test -- tests/integration/xlsx-classroom.test.ts tests/unit/google-io.test.ts
npm test -- tests/components/App.test.tsx tests/components/Roster.test.tsx tests/components/WorksheetImport.test.tsx tests/components/useActivityView.test.tsx
```

HTTP 測試必須能監聽 `127.0.0.1` 暫時連接埠。出現 `listen EPERM` 時屬環境限制，不能當成業務案例通過；在允許本機連接埠的環境重跑。既有版本於 2026-11-17 的基準為 15 個測試檔／43 個案例通過、型別檢查通過；本次實作結果另列於驗證紀錄，不以基準代替。

## 正常及邊界驗收

| 流程 | 正常操作與預期 | 邊界操作與預期 |
| --- | --- | --- |
| 單一啟動 | 根 `.env` 有教師密碼、無組別設定，單一 dev 指令可登入，空名單 | 缺少必要值明確報錯；僅外部設定可啟動；外部值優先；錯誤舊 GROUP_CODES_JSON 不生效；啟動失敗不遺留服務 |
| 組別與碼 | 2 分鐘內建立三組、取得三個不同碼、刪除一組，重新整理／登入後其餘碼不變；開題前更名同步更新已登入學生組名，碼與 memberId 不變 | 空白、重複、41 字拒絕，1／40 字接受；碰撞重新產生；刪組後舊碼及成員失效，重建同名組不重用舊碼 |
| 學生加入 | 30 秒內以碼及名稱加入，學生顯示自身名與組名，老師看到曾加入名稱 | 空白、41 字、無效碼及舊活動拒絕，成員數不變；同組同名冪等、跨組同名允許；emoji／組合字依可見字元計數 |
| 名單鎖定 | 首回合前可修改，首回合後碼與名單仍顯示 | 回合中及回合間新增／更名／刪除皆拒絕；現有組可晚加入，空名單不能開題 |
| 單題 XLSX | 無 Google 設定匯入快照，3 秒內看到 6 主題／6 填空／6 回合並可選題送答 | 表頭與答案橫向合併不重複，答案目標保存主格；插入標題列及移欄後仍相同 |
| 混合 XLSX | 4 主題／6 填空／4 回合，前兩題各兩子題，一次完整送答 | 子題號不是答案；合併主題號不漏子題，完整題號衝突須指出位置與修正方式 |
| 多工作表 | 多張先候選，明選第二張後匯入，不能默用第一張 | 候選、取消選檔、無效 ID 皆保留舊學習單及選題；不因第二張空白改用第一張 |
| 檔案驗證 | 結構有效且恰為 10,485,760 bytes 的 XLSX 接受 | 上限加 1、假格式、空白、損毀、加密、缺必要欄與公式識別拒絕；原有效資料不變 |
| 更換來源 | 首回合前成功換來源後清舊選題與準備回合，保留組、碼、成員，須重新選題 | 驗證未通過或發布前被拒絕保證本次操作零寫入；舊上傳主體未收完而較新 Google 匯入先完成、交叉來源晚回應、匯入中先開題皆不得覆蓋現況 |
| 匯入結果待確認 | 發布成功但 HTTP 回應遺失時顯示「匯入結果待確認」，立即取完整教師快照，確認目前來源及選題後再恢復操作 | 暫時無法連線保持待確認，不能宣告成功或零寫入，不自動重送 POST；確認前禁止再匯入或開題，其他分頁較新資料不回滾；撤權／活動過期則清登入並返回加入流程，不重送舊操作 |
| 斷線與登出 | 老師名單保留名稱；原身分重連或同碼同名重登沿用成員 | 無新事件重連也立即取完整快照，驗證後 1 秒內顯示；刪組／重啟後不能接回；登出清分頁暫存 |
| 同組送答 | 兩畫面共用一筆已接受答案與順位 | 送答已收但回應遺失、另一人已送、回合已結束三種重連均不重送、不改順位；不透露他組進度 |
| 匯出與回填 | XLSX 完成回合後 CSV 正常，Google 副本回填與既有衝突保護正常 | 本機來源拒絕回填且 Google 呼叫數為零；CSV 無學生名與加入碼新欄，無勝組保留原值 |
| 文字與權限 | 角色對應密碼／碼／名稱，移除指定品牌，保留登出；加入碼的伺服器記憶體與學生本人分頁暫存符合憲章 2.0.0 | 切角色清輸入、無「憑證／組別代碼」；登入恢復未完成時登出／切角色，舊成功回應不能自動登入；學生不能操作教師端點或讀完整碼表，教師密碼不存 Web Storage；動態文字不執行標記 |

## 手動重連演練

1. 教師建立甲、乙組，另開兩個學生分頁，以甲組碼分別用小明、小華加入。老師看見兩個曾加入名稱。
2. 匯入 [混合快照](references/mixed-questions.xlsx)，選含兩格的題組並開始；在瀏覽器開發工具將小明分頁設為離線。小華完成送答，老師結束回合。
3. 將小明恢復上線：1 秒內恢復最新可見狀態及最終結果，甲組仍只有一筆送答；姓名不重複。
4. 重做一次斷線期間完全沒有新事件的情況，仍須立即抓完整快照，不能等待 20 秒。
5. 小明登出再以同碼同名登入，名單不重複；另以首回合前刪組及整個服務重啟演練舊身分拒絕。不能在名單鎖定後刪組來製作測試前置條件。

## 測試資料與交付紀錄

原始快照直接作回歸輸入；由測試在暫存目錄產生移動欄列、多頁、公式、損毀及大小邊界副本，不覆寫原始參考檔。大小恰好上限的資料必須仍是有效 XLSX，不能只用任意位元組填滿後測大小。測試密碼與加入碼由隔離測試配置產生，斷言不能在失敗輸出洩漏值。

交付時記錄正常／邊界案例的實際指令、結果、執行版本與未執行原因。Google 寫入測試若無獨立副本或授權，標示未執行，不回填使用者的公開原稿。本指南的契約細節以 [HTTP](contracts/http.md)、[XLSX](contracts/worksheet-import.md)、[介面與啟動](contracts/ui-and-startup.md) 及 [資料模型](data-model.md) 為準。
