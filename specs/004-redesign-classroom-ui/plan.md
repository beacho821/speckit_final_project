# 實作計畫｜教室介面重新設計

**功能識別**　`004-redesign-classroom-ui`\
**Git 分支**　`main`\
**日期**　2026-11-18\
**輸入**　[功能規格](spec.md)

## 摘要

老師登入後從教室列表進入各教室，分頁完成備課、分組和搶答主持。控制台保持教室、回合狀態與階段主操作在首屏。學生以手機單欄完成等待、作答與確認收件。投影以大字顯示已開放題目和收件狀態，依教師登入或組別投影碼決定可見範圍。

保留現有 React 介面元件及 Express 搶答規則，將單一活動改為各教室獨立管理的目前活動與歷史紀錄。以伺服器確認的狀態驅動 UI，每間教室一份 JSON，存檔成功後對學生、老師及投影發布狀態。

## 技術脈絡

| 項目 | 設計 |
| --- | --- |
| 語言與執行環境 | TypeScript、Node.js 22.12 以上，沿用鎖檔中的 React、Vite、Express、Tailwind CSS |
| 資料與整合 | 目前工作目錄的 `classroom-data/<classroomId>.json`。沿用 ExcelJS、Google 學習單匯入與既有成果 CSV、Google 回填流程 |
| 測試 | Vitest 元件、領域單元、HTTP 契約與整合測試，另用真實瀏覽器檢查排版、鍵盤及投影 |
| 執行平台 | 桌面教師及投影瀏覽器、手機學生瀏覽器，既有單進程 Node.js 部署。建置後同源供應前端與 API，本機預設繼續使用 loopback |
| 效能與規模 | 至少兩間教室可同時搶答。依 SC-002，以操作送出至最後一個應更新的授權畫面顯示正確狀態計時。各轉換測 3 次，每次至多 2 秒。各教室獨立排程寫入 |
| 授權 | 既有教師密碼驗證，活動與組別加入碼僅留記憶體。全班投影使用已登入教師分頁的唯讀資料，組別投影使用專用加入碼。單進程啟動時先提交非機敏發碼世代，兩種碼均避開教師密碼。需復原時，只有可信紀錄證明下一世代可安全遞增才重新發碼 |
| UI 範圍 | 教師五頁、學生三種主要狀態。桌面雙欄、窄版自然堆疊、投影以 16:9 為主要驗收版型 |

## 憲章檢查

| 原則 | 規劃前檢核 | 設計後複核 |
| --- | --- | --- |
| 輸入驗證與錯誤訊息 | 教室名稱、活動階段、題組與審核內容均有邊界案例 | HTTP 契約定義拒絕原因與零異動，UI 契約定義錯誤位置、修正指引與焦點 |
| 正體中文 | 規格與現有介面採正體中文 | 新畫面文字、系統錯誤與驗收指南均使用正體中文 |
| 最小可行產品優先 | 重用既有前後端與回合規則 | 沿用瀏覽器 History、既有長輪詢與原生檔案操作，不增加套件或服務 |
| 機敏資料保護 | 依角色及當次活動驗證，憑證在記憶體 | 教師初始密碼來自環境，投影唯讀資料獨立裁剪。組別投影碼同屬當次課堂加入碼。兩種碼分別驗證用途，排除教師密碼與舊世代。結束授權時撤銷 |
| 功能測試 | 核心操作有正常與邊界案例 | 驗收指南覆蓋跨室隔離、重啟、啟動轉換寫入失敗、審核衝突、跨頁開題、回填期間換場衝突及手機操作，實作後以實際測試結果複核 |
| PlantUML 設計優先 | 讀取並採用三張 004 圖 | 組件與接口對應組件圖，聚合與歷史快照對應類別圖，啟動還原、收件及定案順序對應時序圖 |

### 原始碼配置

| 範圍 | 規劃 |
| --- | --- |
| `frontend/src/App.tsx`、`session.ts`、`api.ts` | 保留登入入口及學生重新驗證。教師登入後進教室列表，教室工作區依教室及活動身分掛載 |
| `frontend/src/` | 新增教室列表、教師導覽與投影元件。將目前 `TeacherRound.tsx` 的準備與主持內容拆至對應工作區，重用 `Roster`、`WorksheetImport`、`ManualQuestion`、`RoundReview`、`RoundHistory`、`TeacherResults`、`StudentRound` |
| `frontend/src/styles.css` | 新增登入後版面規則與操作狀態的樣式範圍，維持既有登入畫面的尺寸、欄位和樣式 |
| `backend/src/bootstrap.ts`、`app.ts`、`access.ts` | 啟動載入、教室路由與身分解析。生產啟動採 JSON 存檔，隔離啟動轉換失敗的教室。測試注入記憶體或獨立暫存目錄 |
| `backend/src/` | 新增教室目錄及 JSON 存取模組。重用活動、分組、題目、回合與審核邏輯，於教室內隔離異動及同步。Google 回填期間在同教室的異動序列中阻擋換場與刪除，並以試算表 ID 與工作表 ID 共同限制同目標並行回填 |
| `shared/api.ts`、`tests/` | 教室與活動識別、投影唯讀回應、審核資格與歷史結果形狀。既有測試輔助流程改為顯式建立教室 |

### 實作順序

1. 建立教室身分、存檔、啟動還原及學生登入的教室定位，再以現有正常及邊界案例驗證活動改為教室範圍後的行為。
2. 完成教師教室列表、管理與分組導覽，接上控制台及歷史清單。同一教師分頁的備課與控制台共用開題就緒狀態，切到控制台仍能檢查未儲存修改。
3. 接通學生各狀態及全班／組別投影，驗證切換教室、兩間同步搶答與撤銷授權。
4. 依驗收指南檢查畫面、區網同步、重啟、失敗復原與現有學習單行為。
