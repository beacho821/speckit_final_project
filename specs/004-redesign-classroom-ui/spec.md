# 功能規格｜教室介面重新設計

**功能目錄**　`specs/004-redesign-classroom-ui`\
**建立日期**　2026-11-18\
**狀態**　規格已審閱\
**需求來源**　重新設計教師端與學生端介面，以教室保存分組與挑戰紀錄，並新增課堂投影。初始登入沿用現行設計。

## 澄清紀錄

### 2026-11-18 澄清

- 問　一間教室完成一場活動後，下次「恢復主持」時，老師應該如何調整分組？答　在同一間教室開始新活動，沿用上次分組並允許在開放搶答前調整。舊挑戰保留當時的分組。
- 問　同一台伺服器上的兩間教室，可以同時開放搶答嗎？答　可以。各教室獨立開放、收件、審核與定案，切換教室不影響其他教室的活動。
- 問　全班的教室投影是否需要讓另一台裝置在未登入教師帳號的情況下開啟？答　全班投影由已登入的老師從教室管理頁開啟。獨立裝置可用組別投影加入碼觀看指定組別。

## 使用情境與測試

### 情境一｜建立、恢復與刪除教室（P1）

老師登入後在左側建立教室，或從右側「我的教室」恢復已使用過的教室。以兩間具不同分組和紀錄的教室驗收。

1. 老師以有效名稱建立教室後，進入該教室的活動準備頁，清單顯示新教室。名稱只含空白時顯示修正提示，清單維持原筆數。
2. 在兩間教室各完成一次挑戰後重啟伺服器，老師可在清單「恢復主持」，看到該教室原有分組、題目及已定案紀錄。另一間教室的資料維持獨立。「恢復主持」繼續該教室現有的活動。
3. 刪除前以教室名稱及紀錄移除提醒請老師確認。取消後仍可恢復該教室，確認後該教室從清單消失，既有連線失去授權，重啟後也無法恢復該教室。另一間教室仍可使用。
4. 兩間教室可以同時開放搶答。老師在兩間教室間切換後，兩邊學生仍能各自送答。結束其中一間的搶答後，另一間仍可收件。兩間教室分別審核、定案並保留各自結果。

### 情境二｜設定活動與分組（P1）

老師進入教室管理頁，在準備區匯入或新增題目、選題與確認答題設定。以一間新教室完成備課驗收。

1. 「開啟分組管理」與導覽列「分組管理」進入同一教室的分組頁。老師建立組別後可看到學生加入碼及已加入名單，返回管理頁時仍在原教室。
2. 老師可以預覽題組及小題、編修準備中題幹與標準答案。題幹或標準答案缺漏、沒有組別或有未儲存的編修時，開放搶答操作須指出待完成項目，並維持準備狀態。同一教師分頁從備課切到控制台時，未儲存的題目修改仍會阻止開放，畫面提示「請先儲存題目修改」並提供返回備課入口。
3. 無效或重複組名顯示可修正的提示，保留輸入且原名單不變。活動的名單鎖定後仍可查看組別、名單及加入碼，編輯操作依現有名單鎖定規則停用。
4. 完成一場活動後，老師可從教室管理頁選「開始新活動」，沿用上次分組並在第一次開放搶答前新增、更名或刪除組別。上一場的定案紀錄仍顯示各回合當時的組名與答案。若目前仍在收件或待審核，顯示完成目前回合的提示，教室仍使用當前活動。

### 情境三｜開放搶答、審核與定案（P1）

老師從控制台主持一個題組，驗收開放、結束、審核和查閱答案的完整路徑。

1. 老師點「開放搶答」後，控制台顯示題組與組別送答進度。點「結束搶答」後關閉收件並進入審核。逾時送答有提示且不加入審核清單。
2. 審核時可逐題判對或判錯，也可取消已送出組別在本回合的資格。取消後保留原答案與送答順序供老師查核，並重新判定勝組候選與需補答小題。老師在定案前可撤回取消資格。
3. 每個沒有合格組別答對的小題均可填寫教師補答。缺少必要補答或判分內容已被另一分頁更新時，阻止定案並提示修正。完成後點「確認定案」，逐回合答案列表顯示組別答案、判定、資格、補答及勝組，並可再次開啟查閱。
4. Google 回填進行中，同一教室開始新活動或刪除教室的操作暫停。其他教師分頁送出同樣操作時，應收到「回填進行中，請稍後再試」的提示，原教室和活動維持原狀。另一間教室可照常換場或刪除。
5. 兩間教室若回填同一張 Google 工作表，第二筆在第一筆確認結果前應收到稍後重試的提示，且無寫入。老師重試時須重新核對來源，若前一筆已改動該題而造成衝突，保留既有答案。不同工作表可並行回填。

### 情境四｜學生等待、作答及確認收件（P1）

學生沿用加入碼及名稱登入，在手機上驗收同組兩台裝置的作答流程。

1. 加入後若未開放或正在備題，頁面顯示「等待老師準備題目」與所屬組別。老師開放後自動切至對應題組，逐題顯示題幹與輸入欄。
2. 具送答資格時可按「送出本組答案」。伺服器接受一份完整答案後，同組畫面顯示「本組已鎖定送出」、所屬組別與伺服器接受的逐題答案，答案欄為唯讀。重新整理並通過身分驗證後，仍可看到同一份答案。
3. 缺答、仍在公平等待時間或回合已關閉時，送答遭拒絕並顯示原因。若回應遺失，保留草稿、顯示待確認狀態並同步收件結果，避免自動重送。未收件且已停止搶答的學生看到等待公布的狀態。

### 情境五｜開啟大螢幕投影（P2）

老師從選定教室的管理首頁「開啟教室投影」，或在分組頁替指定組別「產生投影加入碼」，讓另一台裝置開啟該組投影。以兩間教室、兩組及獨立投影裝置驗收。

1. 已登入的老師按下「開啟教室投影」後，畫面以大字呈現教室名稱、階段、已開放題目及各組送答狀態。學生送出或老師定案時同步更新，定案後可顯示已公布摘要。未登入教師的裝置直接開啟全班投影網址，或以組別投影碼嘗試開啟全班投影時，顯示教師登入提示，畫面維持無教室資料。
2. 獨立裝置輸入組別投影加入碼後，看到對應教室與該組的名稱、回合階段、已開放題目與該組收件狀態。無效、失效或跨範圍的授權顯示重新取碼提示，且不載入畫面資料。
3. 投影畫面只有展示功能。未開放題目、未公布答案、學生姓名、學生加入碼及教師操作均不出現在投影。
4. 兩間教室同時搶答時，各自開啟投影。完成一間教室的送答後，只有該教室的投影更新收件狀態，另一間仍顯示其自身進度。

### 邊界情況

- 無歷史教室、無組別、無題目及無定案紀錄時，各頁顯示對應空狀態及可執行的下一步。
- 開始新活動後，上一場活動的學生及投影加入授權失效。老師可發放新活動的加入碼，重新加入後進入新活動的等待畫面。
- 同組多裝置同時送答時，只有伺服器接受的第一份有效答案列入順位。取消資格不解除該組的收件鎖定。
- 伺服器重啟時，原進行中回合轉為待審核並保留已收答案，原準備中及待審核回合恢復原狀。老師重新開啟教室後可繼續處理，學生及投影裝置須取得當次有效碼。重啟後新發的碼可正常登入。即使在全新分頁手動輸入重啟前的學生碼或組別投影碼，也須遭拒。若發碼世代需要復原，只有能確認下一個世代高於最後一次實際發碼的世代，才能重新發碼。只有舊備份且無法確認時，學生碼與組別投影碼維持停用，教師仍可管理已恢復的教室。
- 其中一間教室無法讀取時，老師可使用其他有效教室，並獲得可辨識受影響教室的提示。存檔失敗時顯示失敗與重試指引，保留上一次有效紀錄且不顯示已儲存成功。重啟時若無法保存轉為待審核的結果，保留原檔，將該教室標示為暫時無法恢復並停止提供收件及加入。其他教室照常啟動，下次成功恢復時仍可看到原答案與順位。

## 需求

### 功能需求

| 編號 | 驗收要求 |
| --- | --- |
| FR-001 | 初始登入沿用既有教師密碼與學生加入碼、名稱入口。教師登入後先看到教室列表，學生驗證後直接進到所屬教室與組別。 |
| FR-002 | 桌面教室列表左側是建立表單，右側是「我的教室」歷史清單。清單顯示教室名稱、最近更新時間、「恢復主持」與「刪除教室」。窄螢幕按建立表單、清單順序排列。 |
| FR-003 | 老師可建立、恢復或經確認刪除指定教室及其紀錄。教室各自保存分組、題目設定及跨活動的挑戰紀錄，不同教室可同時開放搶答、收件與審核。切換畫面、控制回合及刪除教室只影響選定教室的相關操作與資料。「恢復主持」繼續現有活動。「開始新活動」沿用分組，只有當前活動無收件中或待審核回合，且該教室的 Google 回填已結束時可用。回填期間也暫停刪除該教室。同一張 Google 工作表同時只接受一筆回填。再次嘗試須核對最新來源，原值衝突時拒絕覆寫。 |
| FR-004 | 教室管理首頁是活動準備與設定頁，提供題源匯入與預覽、手動新增題目、選題及備題設定，以及「開啟分組管理」「開啟教室投影」和進入控制台的入口。同一教師分頁的備課及控制台共用待確認與未儲存修改狀態，完成儲存後才可開放搶答。教室管理、分組管理及老師控制台以一致導覽顯示教室名稱、當前頁面及返回教室列表入口。全班投影只呈現教室名稱、階段及依 FR-008 可顯示的資訊。 |
| FR-005 | 獨立分組管理頁可由首頁按鈕與導覽列進入。新活動沿用上一場的分組，可在首次開放搶答前新增、更名與刪除。本場首次開放搶答後鎖定分組，歷史回合仍保留當時的分組。學生使用當次活動的學生加入碼。每組提供「產生投影加入碼」。 |
| FR-006 | 獨立老師控制台依回合階段顯示可用操作，包含「開放搶答」「結束搶答」，並顯示目前題組、階段、各組送答狀態與可查閱的「已定案答案」列表。 |
| FR-007 | 審核支援逐題判對錯、取消及恢復已送出組別的本回合資格、教師補答、確認定案。取消資格的組別不參與勝組或有效正解計算。定案前驗證補答完整性與審核版本，定案後結果唯讀。 |
| FR-008 | 教室及指定組別投影以唯讀大螢幕介面顯示教室、階段、已開放題目及授權範圍的收件狀態。全班投影須由已登入的老師從教室管理頁開啟。組別投影加入碼可供獨立裝置唯讀觀看指定教室與組別。用於全班投影、學生登入或教師登入時須拒絕。 |
| FR-009 | 學生畫面依伺服器狀態自動切換等待、作答及已送出畫面，全程辨識所屬組別。作答畫面有題組、逐題輸入欄和「送出本組答案」，已送出畫面載入伺服器接受的逐題答案並停止編輯。 |
| FR-010 | 伺服器在目前專案目錄使用專用存檔資料夾，一間教室一份 JSON 紀錄，成功的教室資料異動自動儲存、啟動時自動讀取。存檔範圍包括教室設定、分組及成員資料、題目、回合答案和審核結果。存檔使用流程只有自動儲存與載入。 |
| FR-011 | 教室管理權限沿用既有教師登入。每個有效的學生加入碼只對應一間教室的當次活動與一個組別。學生碼與組別投影碼各有專用用途，兩種碼均不得與教師密碼相同，重啟前曾發出的碼不得在重啟後重新發放。學生與投影僅能讀取已授權的教室及資料。教室刪除、對應組別刪除、開始新活動或伺服器重啟使相關授權失效。教師密碼、學生加入碼、投影加入碼與其他機敏憑證不寫入教室存檔。 |
| FR-012 | 登入後介面使用正體中文，主要動作、目前階段與錯誤提示可由文字辨識。桌面教師頁以導覽與工作區排列，手機學生頁採單欄，投影集中顯示大字題目與狀態。所有主要操作支援鍵盤並顯示焦點。 |

### 主要資料

- **教室**　名稱及最近更新時間，包含題庫、目前活動及歷次活動紀錄。
- **活動**　隸屬一間教室，記錄分組、名單鎖定狀態及挑戰回合。每間教室有一個目前活動。
- **組別**　隸屬單一教室，包含組名與學生名單。當次學生及投影授權各有用途與範圍。
- **挑戰回合**　隸屬教室的一場活動，記錄題組、所屬階段、當時分組、各組伺服器收件內容與順位。
- **定案結果**　記錄各題判定、組別資格、教師補答及勝組，隨教室保留供查閱。

## 成功標準

### 可量測成果

- **SC-001**　在桌面及手機各走查一次，教師端五種頁面及學生端三種主要狀態均可依指定入口或回合狀態到達。學生在 360 像素寬的畫面可完成整組作答而無須水平捲動。
- **SC-002**　在同一個區域網路，以一位老師、兩個學生組別及一台投影裝置測試。開放、結束、收件和定案各測 3 次。以教師或學生送出有效操作為起點，到最後一個應更新的已授權畫面顯示正確狀態為終點，逐次記錄相關教師、學生和投影畫面的更新時間。每次均須在 2 秒內。另同時開放兩間教室，各收取至少一份答案，依序結束並定案，核對每間教室只記錄本教室的收件與結果。
- **SC-003**　建立兩間教室，各含至少兩組及兩筆已定案紀錄。重啟後均可恢復全部預期的組別、答案與判定。刪除其中一間並再次重啟後，另一間資料全部可查閱，已刪教室的舊授權均遭拒絕。
- **SC-004**　由 3 位試用者分別走完教師、學生及投影路徑。每位均能依畫面文字完成各自的主要操作，並正確指出目前教室與回合狀態。

## 假設

- 「首頁」指選定教室後的管理首頁。全班投影與組別投影依各自的授權範圍呈現資料。
- 伺服器重啟後，「恢復主持」可繼續重啟前的活動。重啟將搶答中回合轉為審核，以保留既有收件並避免沿用重啟前的送答時間。新加入碼可由老師在恢復主持後發放。
- 「取消資格」作用於已送答組別的該回合，資格可於定案前恢復。公平等待規則、手動與學習單出題、活動成果 CSV 及原有回填確認流程沿用既有行為，回填期間的同教室換場與刪除依本規格處理。
- 「我的教室」沿用目前部署的教師密碼授權範圍。建立教室以名稱為必填，清單以最近更新優先排列。
