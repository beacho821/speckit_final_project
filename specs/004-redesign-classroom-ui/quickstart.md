# 驗收指南｜教室介面重新設計

本指南驗收 [功能規格](spec.md) 所列操作。命令及預期結果供功能實作後執行。

## 準備與執行

在專案根目錄使用 Node.js 22.12 以上。建立本機 `.env` 並填入測試用 `TEACHER_PASSWORD`。使用測試教室及測試成員，匯入可用既有測試 XLSX 或手動輸入題目。

```sh
npm ci
cp -n .env.example .env
npm run typecheck
npm test
npm run build
npm run dev
```

開啟終端輸出的開發網址。HTTP 測試需能在 loopback 監聽暫時連接埠。區網手機與投影驗收使用建置產物，由既有 Node 服務同源供應。結束開發服務後，用下列方式啟動預留的區網測試模式，手機及投影裝置連至開發機區網位址，教師可在開發機用 loopback 操作。有 HTTPS 同源入口的部署可從該入口驗收。

```sh
npm run build
HOST=0.0.0.0 npm start
```

`HOST` 為本功能規劃的啟動參數，未設定時使用本機 loopback。兩種啟動方式皆以目前工作目錄的 `classroom-data/` 保存測試教室。

## 驗收案例

| 功能 | 正常案例 | 邊界案例與預期 |
| --- | --- | --- |
| 教室列表與恢復 | 桌面登入看左側建立、右側清單。建立兩間不同教室，返回清單後各以「恢復主持」開啟原進度。 | 全空白名稱顯示欄位錯誤且清單原筆數不變。取消刪除仍可進入。確認刪除後舊連線撤權、重啟後仍沒該教室。 |
| 獨立搶答 | 兩間各建立兩組，保持兩間收件中並切換教師畫面。各室送答與定案皆落在原教室。 | 結束第一間並保留第二間正在收件。帶第一間的學生授權前往第二間請求時遭拒絕，第二間與第一間均無多餘資料。 |
| 活動與分組 | 由按鈕及導覽進入同一分組頁，調整名單、備題、開放並定案。開始新活動後沿用分組，再更名並查上一場組名。 | 輸入重複組名、鎖定後編輯或在收件／待審核時開始新活動均被拒。舊碼在新活動無法使用。備課頁留下未儲存的題目修改再切到控制台，須阻止開放並提供返回入口，儲存後可開放。 |
| 審核與定案 | 同回合收到兩組答案。改判並取消一組資格，核對原答案、順位及補答需求。恢復資格後重新計算。完成合理補答及定案後查看完整唯讀結果。 | 缺必要補答或另一分頁先修改時，定案遭拒並顯示修正指引。舊草稿可核對，歷史未增加。 |
| 手機作答 | 以 360 px、同組兩裝置完成等待、作答與收件。重新整理後同組顯示伺服器接受的答案且無水平捲動。 | 嘗試缺答、公平等待中送出、關閉後送出。模擬回應遺失後重新同步，不自動重送。同組並行提交只接受一份。 |
| 投影 | 由教師頁開啟全班投影，同時留在控制台。另一台裝置輸入組別投影碼。同時開啟兩間教室投影，確認只更新操作所屬教室的收件狀態。 | 未登入直開全班投影、以組碼開全班投影、用過期碼、以碼跨組均遭拒且不顯示資料。確認未公開題目、未定案答案與學生姓名均未送至投影。 |
| JSON 與重啟 | 兩間教室各兩組、兩份定案紀錄。重啟後驗證兩間資料相同。再令一間處於收件中並重啟，該回合轉待審核且收件與順位不變。 | 在獨立測試資料夾驗證破損教室檔與啟動轉換寫入失敗。受影響教室保留原檔且不可恢復或收件，其他教室可用。下次成功重啟後，原答案及順位均保留。HTTP 整合測試注入儲存失敗，核對回應、畫面版本與上次有效檔案均一致，再重試成功。 |
| 加入碼世代 | 重啟前記下學生碼與組別投影碼。重啟後取得新碼並分別從全新分頁加入。 | 全新分頁手動輸入舊碼遭拒。注入等於教師密碼的候選碼，驗證服務重新產碼。測試輸出避免顯示實際碼值。 |
| Google 回填並行 | 對有可回填結果的教室啟動回填，待作業結束後可依一般條件換場或刪除。 | 用測試替身暫停遠端回填。其他分頁同室換場或刪除均收到 409、顯示稍後再試，確認教室及目前活動無異動。另一教室可操作。 |
| 兩間教室回填同一工作表 | 同一工作表同題準備不同勝組答案。第一筆回填完成後，第二間重新提交時須讀取最新來源並因同題原值衝突而拒絕覆寫。不同工作表可同時回填。 | 暫停第一筆回填於讀回確認前，第二筆同目標立即回傳 409 且零寫入。核對第一筆答案保留。作業失敗後確認目標已釋放。 |
| 發碼世代復原 | 在獨立測試資料夾模擬世代檔損壞，準備可證明最後發碼世代的可信紀錄。停機時恢復已確認的世代上限再啟動，驗證新碼世代較高、舊碼遭拒。 | 只有舊備份且無法證明上限時，保留損壞或缺檔狀態。驗證學生及組別投影的發碼與用碼回傳 503，教師仍可管理其他已恢復教室。 |

## 同步時間驗收

在同一區網以一位老師、兩個學生組別及一台投影裝置操作。以教師或學生送出有效操作為起點，到最後一個應更新的授權畫面顯示正確狀態為終點。以同一計時來源記錄起點及各應更新畫面的時間，例如以單一拍攝裝置放入同一段錄影。開放、結束、收件及定案各做三次，逐次記錄，每次均須在 2 秒內。

## 版面與鍵盤驗收

- 以桌面 1440 px、窄版 768 px、手機 360 px、瀏覽器 200% 縮放及 1280 × 720 投影收集畫面。一次檢查各代表狀態，再以一輪修正後確認。
- 以長教室名、組名、長題幹及多回合歷史確認換行、按鈕鄰近性、捲動及首屏操作。核對鍵盤焦點、刪除確認、表單錯誤、收件狀態與手機虛擬鍵盤。
- 由教師、學生、投影三位試用者各走一次對應路徑。記錄是否能完成主要操作並說出教室與階段。版面細節見 [UI 契約](contracts/ui.md)。
