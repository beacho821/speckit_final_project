# 資料模型｜教室、活動與挑戰紀錄

對應 [類別圖](../../diagrams/004-class.puml) 與 [時序圖](../../diagrams/004-sequence.puml)。

## 持久資料

| 實體 | 主要欄位與關聯 |
| --- | --- |
| 教室 | `id`、`name`、`createdAt`、`updatedAt`、`currentActivityId`、題庫和學習單來源、至少一場活動。教室名稱去除頭尾空白後限 1–40 個可見字元，同名教室依獨立識別與更新時間區分。 |
| 活動 | `id`、`startedAt`、`archivedAt`、`rosterVersion`、`rosterLocked`、組別、成員及回合。每間教室恰有一場未封存的活動。教師查歷史時按活動與回合分組。 |
| 組別及成員 | 組別具 `id`、`name`。成員具 `id`、`groupId`、`name`，保留既有同組同名規則。活動內的組名依既有限制驗證。回合保留開放時組別識別及組名快照。 |
| 題庫及題組 | 沿用 `CatalogUnit`、`RoundQuestion`、`Worksheet`。回合開放時保存題組名稱、題號、題幹、標準答案及回填定位快照，以維持歷史內容。 |
| 挑戰回合 | `id`、`unitId`、`phase`、公開題組快照、分組快照、收件、`reviewRevision`、教師補答及勝組。每場活動最多有一個未定案回合。 |
| 組別收件 | `groupId`、`rank`、伺服器接受的各題答案、原判與改判、`disqualified`。同回合一組最多一份，順位依伺服器接受順序。取消資格只改資格標記。 |
| 定案結果 | 已定案回合內容是歷史原本，由來源快照、各組結果、補答及勝組組成。逐題查詢產生角色可見的資料。 |

存檔外層有 `schemaVersion: 1`，檔名由伺服器產生的教室識別決定。載入驗證版本、檔名對應、欄位形狀、父子關聯及回合狀態。資料目錄排除於版本控制與公開前端路徑。舊版應用只有記憶體活動，部署後首次使用由老師建立教室。

另以 `classroom-data/issuance-epoch.json` 保存非機敏的單調遞增發碼世代。單進程每次啟動先以原子寫入提交下一世代，再開放發碼。既有資料目錄缺少發碼世代檔、世代值無效或寫入失敗時，停用兩種加入碼的發放與驗證並提示教師修復，禁止重設或沿用舊世代。教室各自照正常還原流程處理。

發碼世代復原由管理者在伺服器停止時執行。使用可信紀錄確認最後實際發碼世代或其上限，例如停機後取得且可確認後續未再啟動發碼的世代檔。只有能確認這個上限時才可還原世代檔，填入等於或高於上限的值，再由啟動流程原子遞增並開放發碼。舊備份本身不足以證明上限，無法確認時保留發碼停用狀態，教師仍可管理已恢復的教室。

## 執行期授權與同步

- 執行期識別區別同一活動在重啟前後的授權。老師的當前工作區由教室識別、活動識別及執行期識別定位。切換教室時，以新識別載入完整快照。
- 學生及組別投影碼使用各自用途，對應目前教室及活動內的一組。碼包含可明確解析的發碼世代及伺服器隨機產生的部分，驗證時先確認當次世代再查碼表。首次建立全新資料目錄時初始化世代檔，其餘啟動均遞增現有值。依登入驗證使用的正規化規則比對，生成結果與教師密碼相同時重新產碼。有效碼及本進程已用碼跨教室與用途不重複。組別建立或恢復時可配置投影碼，由教師明確執行「產生投影加入碼」啟用並取得；重按取得該組當次有效碼。
- 異動成功後通知各受影響範圍，各範圍維持自己的快照版本。長輪詢回應前重新檢查授權，撤銷時立即結束對應等待。畫面可見資料由伺服器依角色投影。
- 教師密碼、學生碼、投影碼、同步版本、匯入世代、執行期授權查表與單調時計時均屬執行期。已收件的穩定順位和需要展示的時間則保存在教室資料內。
- Google 回填的進行中狀態屬教室執行期，綁定開始時的活動與資料快照。在該教室的異動序列內設立並解除標記，網路操作期間釋放佇列。換場及刪除在同一序列內拒絕進行中回填。另以試算表 ID 與工作表 ID 的組合記錄各目標的進行中作業。工作表保留狀態涵蓋讀取來源至讀回確認。不同工作表可並行。

## 生命週期

| 事件 | 狀態與歷史 |
| --- | --- |
| 建立與恢復主持 | 建立時有一場備課狀態的新活動。恢復主持定位原教室的目前活動，其他教室照原狀執行。 |
| 開始新活動 | 拒絕仍在收件、待審核或該教室仍在 Google 回填的操作。封存既有活動與已定案回合，撤下未開放的準備回合；沿用組別設定及教室題庫，新活動由空白回合與可編輯名單開始。撤銷前一場學生及投影授權。 |
| 搶答與審核 | `idle → preparing → active → reviewing → ended`。首次進入 `active` 鎖定活動名單。結束時判分，審核改判、資格及補答共用版本。定案後保留唯讀快照。 |
| 存檔與回報 | 同一教室的持久異動逐筆執行。先驗證與產生草稿，原子保存後才提交記憶體版本及回傳。並行收件的驗證對最新已提交狀態進行。 |
| 重啟與刪除 | 啟動逐檔驗證，收件中轉待審核並先保存，沿用原收件及順位。個別壞檔或轉待審核寫入失敗時保留原檔，該教室暫時無法恢復、收件及加入，其他教室仍可用。下次啟動重新嘗試還原。刪除須等該教室回填結束，先完成檔案移除，再撤銷教室及授權。 |
