# HTTP 契約｜教室與活動

## 身分及範圍

所有私有回應沿用 `Cache-Control: no-store`。既有教師密碼與學生加入碼使用現有驗證方式。教師登入後可列出教室，選室後伺服器回傳該教室目前活動的定位資料。

- 活動端點以登入回傳的 `classroomId`、`activityId`、`activityEpoch` 定位。使用 `X-Classroom-Id`、`X-Activity-Id`、`X-Activity-Epoch`，學生另提供 `X-Member-Id`。伺服器將這些值與已驗證的授權比對。學生同分頁重新整理依上次活動定位重新驗證。
- 查詢或異動在開始及必要的完成階段核對教室、目前活動及授權。刪室、刪組、換活動或重啟使對應舊授權失效。各頁長輪詢送出回應前重新驗證。切換教室只改該教師工作區的定位。
- 全班投影由教師請求獨立 API。原教師分頁維持固定教室及活動的唯讀投影資料訂閱，使用同源訊息傳送至自己開啟的視窗，雙方比對明確來源與視窗身分。網址與投影訊息只傳畫面識別或已裁剪資料。登出、失效或來源視窗中斷時清除資料並提示重新開啟。
- 組別投影加入碼由獨立入口輸入，當次分頁只在記憶體保留。各次唯讀請求在 `Authorization` 傳送組別投影碼，不接受跨組覆寫。學生及組別投影新登入都檢查目前發碼世代和用途。舊碼在沒有舊工作階段標頭的新請求中也回傳 401。兩種發碼路徑都排除教師密碼。發碼世代無法提交或無法安全復原時，發碼及用碼登入端點回傳 503。復原依資料模型的可信紀錄與遞增流程處理。

## 對外端點

| 方法及路徑 | 呼叫者 | 請求與成功結果 |
| --- | --- | --- |
| `POST /api/sessions` | 老師、學生 | 保留登入欄位。老師回傳角色，學生以碼及姓名解析唯一教室與組別，回傳角色、教室、活動、執行期、成員及組名。 |
| `GET /api/classrooms` | 老師 | 回傳依更新時間降冪的教室列表，含名稱、識別、階段及是否正在回填。個別無法讀取的紀錄以教師可辨識的項目顯示提示。 |
| `POST /api/classrooms` | 老師 | `{name}`。有效時建立教室及首場活動，持久化後回傳 201 與該教室定位。 |
| `GET /api/classrooms/:classroomId` | 老師 | 查詢選定教室、目前活動與回填進行中狀態。供恢復主持及載入教師子頁。若重啟轉待審核寫入失敗，回傳 503 與暫時無法恢復的提示。 |
| `DELETE /api/classrooms/:classroomId` | 老師 | UI 確認後送出，刪除存檔、撤銷授權後回傳 204。教室不存在回傳 404。該教室正進行 Google 回填時回傳 409，教室與資料不變。 |
| `POST /api/classrooms/:classroomId/activities` | 老師，需目前活動定位 | 建立同教室的新活動並回傳 201 與新定位。收件中、待審核或該教室正進行 Google 回填時回傳 409 且零異動。 |
| `GET /api/classrooms/:classroomId/activities/history` | 老師 | 依封存順序回傳該教室的歷史活動，含各場活動的識別、起訖時間、當時組別及成員姓名。回應僅提供唯讀名單所需欄位。 |
| `GET /api/classrooms/:classroomId/results` | 老師 | 跨活動的已定案摘要，按活動、回合呈現名稱、定案順序及勝組。 |
| `GET /api/classrooms/:classroomId/activities/:activityId/rounds/:roundId/results` | 老師 | 已定案回合的唯讀結果，含逐題答案、判定、資格、順位、補答及勝組。 |
| `POST /api/groups/:groupId/projection-code` | 老師，需活動定位 | 產生或取得該組當次的有效投影碼，回傳碼與組別識別。名單已鎖定時仍可使用。 |
| `POST /api/projections/group/session` | 投影裝置 | 驗證組別投影碼，回傳投影範圍及初始快照。 |
| `GET /api/projections/group/view?after=:version` | 投影裝置 | 驗碼後依對應組別取得初始或後續唯讀快照，等待逾時且無變更回傳 204。 |
| `GET /api/classrooms/:classroomId/projection?after=:version` | 老師，需活動定位 | 全班唯讀投影快照及後續更新，等待逾時且無變更回傳 204。 |

沿用 `/api/roster`、`/api/groups`、`/api/worksheet/import`、`/api/questions`、`/api/rounds`、`/api/view`、`/api/results.csv`、`/api/worksheet/writeback` 及既有子路徑。這些端點改由同一活動定位規則解析。既有輪詢、匯入選擇、題目版本、名單鎖定、送出順位、公平等待、CSV 與 Google 回填仍適用。CSV 與回填只取該教室目前活動。非同步題源匯入完成時再核對教室、活動及匯入世代，避免切換或刪除後寫入舊狀態。

回填開始時，在教室的異動序列中確認目前活動並記錄進行中狀態。完成或依既有錯誤及讀回確認流程結束時解除。回填期間同教室的換場及刪除回傳 409（`WRITEBACK_IN_PROGRESS`），訊息為「回填進行中，請稍後再試」。快照及回填目標維持原先選定的活動。

`POST /api/worksheet/writeback` 以來源的試算表 ID 與工作表 ID 作為目標。開始遠端作業前取得該目標的處理權，涵蓋讀取來源、比對、寫入及讀回確認。目標已被任何教室占用時，回傳 409（`WRITEBACK_TARGET_BUSY`）及「此工作表正在回填，請稍後再試」，該次請求不寫入。作業結束或失敗時釋放目標。手動重試重新讀取來源，若原值衝突則沿用 `WRITEBACK_CONFLICT` 拒絕覆寫。不同工作表可以並行，既有同教室換場與刪除限制仍適用。

啟動時個別教室的收件回合若無法提交轉待審核，該教室不註冊有效加入授權，拒絕恢復主持、收件與加入。教師列表顯示可辨識的問題及重啟重試指引，其他教室仍予載入。

## 審核、學生及投影回應

- `PATCH /api/rounds/:id/review` 沿用 `reviewRevision`、`grades`、`supplements`，追加可選的 `eligibility`，每項含 `groupId` 和 `disqualified`。先套用同次送出的判定及資格至草稿，再驗證教師補答。版本過期、無收件組別或重複項目拒絕整筆異動。補答需求與勝組依仍具資格的答案重算。`POST /api/rounds/:id/publish` 驗證版本與所有必要補答後才發布。
- 學生快照可含教室、組別、階段、已開放題組、公平等待及本組收件答案。伺服器確認前維持送出待確認；同組重送回傳可辨識的已收件錯誤，畫面再同步本組已接收答案。下一回合取代先前鎖定狀態。
- 投影快照只傳教室名稱、階段、公開題組、授權範圍的收件狀態及定案摘要。組別投影在狀態與摘要均限該組。待審核前後均排除未定案學生答案、標準答案、學生姓名、加入碼及教師操作資料。沒有目前回合時可呈現本活動最新定案摘要，開始備題後隱藏該摘要。
- 驗證失敗用既有 `ApiError` 形狀與正體中文指引。輸入錯誤 422，未驗證或撤權 401，角色不符 403，查無已授權資源 404，階段或版本衝突 409，未能持久化 503。存檔失敗維持上一版及已發布狀態。錯誤回應不包含憑證、檔案內容或無權查閱的教室名稱。
