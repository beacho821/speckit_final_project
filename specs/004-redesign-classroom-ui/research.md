# 研究決策｜教室介面重新設計

## 版面與互動

**決策**　使用 Impeccable 的操作型介面指引調整現有產品。排序以「教室與階段 → 目前可執行的操作 → 支援資訊」為主。教師以穩定導覽切換工作區，學生及投影按伺服器狀態變化。

**理由**　`frontend/src/App.tsx` 現有工作台依分組、匯入、回合、成果垂直排列。`frontend/src/TeacherRound.tsx` 同時處理準備、開放、審核與歷史，主要控制容易落在首屏下方。`frontend/src/styles.css` 主要按鈕共用全寬樣式，區塊在桌面看起來權重相近，窄版已有部分換行策略可沿用。獨立以 Impeccable layout 掃描 `frontend/src` 回傳空陣列，結構診斷以這些來源檔為依據。

**考量過的做法**　單頁錨點可以沿用既有結構，但無法穩定呈現活動中的主操作。所有頁都採固定雙欄會使手機作答與長題組的閱讀順序變差。採用各頁自己的內容分區並共享導覽、文字層級與階段提示。

## 路由與讀取狀態

**決策**　利用 Express 已有的 SPA 回退與瀏覽器 History 路徑。老師驗證後先到教室列表，教室頁以教室識別為路徑。前端記憶體中的教師登入狀態和已選教室工作狀態獨立管理。既有完整快照及版本長輪詢沿用，並用當次教室、活動及授權範圍約束每項操作。

**理由**　`useActivityView` 已支援取消請求、斷線重抓和版本同步。切換教室時，畫面與同步請求必須一起換範圍，避免低版本新教室被原教室的名單擋住。教師在同一教室的子頁切換保留準備草稿，管理頁及控制台共用開題就緒狀態。學生收件由伺服器確認，失去回應時重抓快照再決定可否送出。

**考量過的做法**　全伺服器只有一間「目前教室」會中斷其他進行中活動。增加路由框架或改為即時連線協定對現有頁數與同步需求無必要。

## 教室存檔與重啟

**決策**　單進程啟動前載入教室清單，每教室以獨立序列完成驗證、草稿異動及寫盤，再更新記憶體並通知授權畫面。存檔以同目錄暫檔、完整寫入及原子重新命名提交。破損檔保留原檔並僅回報受影響的項目。

**理由**　失敗時能保留上次有效紀錄且不宣告操作成功。不同教室互不阻塞。重啟時，對收件中回合沿用結束收件的領域邏輯，轉待審核並在開始接受連線前提交；轉換存檔失敗時保留受影響教室原檔並暫停恢復與收件，其他教室照常啟動。其他回合狀態與已收答案保持原貌。啟動先保存單調遞增的非機敏發碼世代，兩種碼使用新世代及獨立用途，且排除教師密碼。碼表仍僅在記憶體，舊碼即使手動輸入也無法驗證。復原時須有可信紀錄證明最後發碼世代或其上限，無法證明時停用發碼及用碼驗證。

**考量過的做法**　直接覆寫可能只寫到半份資料。背景批次寫入會在崩潰時遺失已回報成功的操作。單一共用 JSON 會讓所有教室共用故障及鎖定範圍。

## 活動與定案歷史

**決策**　教室保存題庫及其來源，開始新活動時沿用題庫和分組設定。公平等待、已用題組、名單鎖定及身分授權依活動重新開始。成員名稱保留在原活動的歷史名單，新活動由當次實際加入建立名單。歷史回合保留題幹、組名、收件、順位、資格、改判和補答快照。

**理由**　老師可在同一間教室再用題目或調整分組，並查到過去活動的原始內容。來源匯入、回填及成果操作維持活動範圍，歷史答案從老師控制台跨活動查閱。Google 回填期間禁止同教室換場及刪除，讓進行中的外部作業保持原活動上下文。共用來源工作表的回填由試算表與工作表識別限制並行，避免兩筆作業都依舊值通過比對。不同工作表仍可並行。取消資格保留原答案與排名，從有效正解、補答需要與勝組計算中排除。恢復資格時重算。

**考量過的做法**　重用舊活動物件或直接重設其回合會破壞歷史。把取消資格實作成刪除收件會遺失證據，也可能讓學生二次送出。

## 投影與部署

**決策**　全班投影由已登入教師分頁開啟同源視窗。教師分頁取得後端裁剪的唯讀快照並傳給該視窗。組別投影則以該組獨立投影碼直接取得唯讀快照。兩條路徑共用顯示元件。既有本機開發使用 loopback，跨裝置驗收用同源區網入口。

**理由**　教師可保有控制台並用另一視窗投影，不需讓獨立裝置取得教師密碼。組別碼可用於教室內獨立裝置，仍限制在指定活動和組別。兩種投影均可依活動階段控制題目及已公布摘要。現行 Express 與 Vite 均綁定 127.0.0.1，跨裝置須使用區網入口。

**考量過的做法**　把教師密碼或投影碼放入網址會進入瀏覽歷史或紀錄。讓投影直接重用教師的完整狀態會包含未公開答案或名單。全班投影另發通用觀看碼超出已確認的授權方式。
