# 實作計畫：教師定案與學生倒數提示

**Git 分支**　`main`  
**功能識別**　`007-clarify-round-feedback`  
**日期**　2026-11-23  
**需求**　[功能規格](spec.md)

## 摘要

沿用控制台審核流程及既有回合快照，在定案操作區呈現缺答、儲存、分頁衝突與定案回饋。採逐筆比對處理不同分頁的判分與補答，用現有版本檢查防止後來的更新被覆蓋。學生送出區依權威剩餘時間顯示正確等待原因，倒數結束時保留草稿。

## 技術背景

| 項目 | 設計決策 |
| --- | --- |
| 語言與執行環境 | TypeScript，Node.js 22.12 以上，沿用單一 npm 專案。 |
| 主要相依套件 | React、Vite、Express 與既有介面樣式。 |
| 資料 | 沿用 `classroom-data/` 的教室與已存審核。尚未儲存的草稿、衝突選擇及操作回饋保存在目前分頁。 |
| 測試 | Vitest、既有 DOM 元件與 HTTP 契約測試，以及真實桌面瀏覽器的頁尾與鍵盤驗收。 |
| 目標平台 | 現有本機教室網頁，操作區依可用畫面寬度排列。 |
| 效能 | 使用既有快照同步。等待秒數依本機經過時間計算。歸零後在仍收件時直接恢復送出，不依賴額外往返。 |
| 限制 | 沿用現有版本檢查、回合封存、師生授權、判分、補答與公平規則。 |
| 範圍 | 同回合的兩個教師分頁與學生作答區。重點涵蓋 10 項功能需求及 SC-001 至 SC-004。 |

**結構決策**　依組件圖以控制台呈現回合規則與操作回饋。以類別圖的回合關係管理草稿及結果。依時序圖核對收到操作結果及學生可送出時機。前端採現有操作與結果查詢，後端沿用既有原子寫入和版本檢查。

## 階段 0 — 研究

[研究紀錄](research.md)已確認分頁比對的現有快照欄位、定案查核入口、就地操作回饋及公平倒數來源。

## 階段 1 — 設計與交付驗收

1. 依[資料模型](data-model.md)保存教師草稿的基準值，將最新已存值與本機草稿逐筆比對。選擇與實際寫入分開，提交使用核對後的目前版本。
2. 依[介面契約](contracts/review-and-countdown.md)讓審核操作取得結構化結果，檢查目前活動及回合。保留操作區的結果和焦點，處理明確拒絕及結果待確認。
3. 依本組剩餘時間更新學生提示，在介面和送出入口核對目前階段。保留同回合草稿，並以現行伺服器拒收回應校正。
4. 依[驗收指南](quickstart.md)核對 SC-001 至 SC-004、資料未寫入的拒絕情境，以及長題組頁尾定位。實作完成後比對三張設計圖與實際流程。
