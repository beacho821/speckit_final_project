# 介面契約：審核操作與學生倒數

相關規則見[功能規格](../spec.md)與[資料模型](../data-model.md)。

## 教師審核操作區

| 狀況 | 使用者可觀察的契約 |
| --- | --- |
| 缺少有效補答 | 依題目順序在「確認定案」旁列出完整題號及填寫、儲存指引。啟動「前往第一個待補答」後，第一個可編輯且待填的欄位取得焦點。 |
| 有待儲存修改 | 就地顯示尚未儲存。儲存與定案各自綁定目前回合，尚未確認前阻止重複操作及定案。 |
| 異值衝突 | 每筆顯示最新已存值與草稿值，以及題號、適用的組別或資格項目。兩個選項可用鍵盤操作。逐筆解決後才可儲存，選擇本身不寫入。 |
| 儲存成功 | 依已確認的新審核內容顯示可定案或缺少條件。 |
| 定案進行中或已成功 | 在原操作區顯示「定案中」，完成後顯示「已定案」與勝組名稱或「無勝組」。狀態區在審核畫面卸載後仍可閱讀。原控制項移除時，焦點移到同區的結果。 |
| 明確遭拒 | 在原操作區顯示原因與下一步，保留輸入。需要更新版本時重新載入並核對。 |
| 結果待確認 | 顯示「結果待確認」。重新載入區分已完成、可重試或仍需確認。核對期間阻止重送，提供就地重新取得狀態的方式。 |

停用的操作旁須有可見原因。載入及完成以可讀出的狀態提示呈現，錯誤使用可讀出的錯誤回饋。操作區隨畫面寬度調整，鍵盤順序仍須可預期。以長題組從頁尾按下操作作為位置驗收。

## 沿用的 HTTP 介面

使用 `activityHeaders` 加入現有身分與活動範圍。錯誤保留現有 `code`、`message` 與適用的 `details`。

| 介面 | 本功能使用的欄位與行為 |
| --- | --- |
| `GET /api/view` | 教師快照使用 `roundId`、`phase`、`closedRoundIds`、`groups` 和 `review` 做版本與欄值比較。學生使用 `phase`、`roundId`、`received`、`waitRemainingMs`。 |
| `PATCH /api/rounds/:id/review` | 傳入 `reviewRevision` 與有實際變更的 `grades`、`supplements`、`eligibility`。成功回傳 `ReviewView`。`409 REVIEW_REVISION_CHANGED` 取得新快照後逐筆比對，拒絕的更新不得部分寫入。 |
| `POST /api/rounds/:id/publish` | 傳入 `reviewRevision`。成功回傳相符的 `id`、`phase: 'ended'` 及 `winnerGroupId`。既有 `422 SUPPLEMENT_REQUIRED` 附帶題目識別，版本或階段不符以原錯誤回應。 |
| `GET /api/rounds/:id/results` | 結果待確認時，新教師快照若已封存該回合，再查該回合結果。從 `winnerGroupId` 與其對應的 `groupName` 顯示結果。學生查詢沿用現有角色限制。 |
| `POST /api/rounds/:id/submissions` | 學生沿用 `answers`。`WAIT_REQUIRED` 的 `details.waitRemainingMs` 校正倒數，既有階段與收件規則仍由伺服器判定。 |

更新與結果回應須屬於此次操作的同一活動和回合。教師快照中僅看到 `idle` 時，須以目標回合識別核對是否封存。勝組名稱暫時取不到時，顯示已知的狀態及查核方式，避免把未知名稱顯示成「無勝組」。

## 學生送出區

- 等待時顯示其他組別優先、可以先填答和剩餘秒數。送出停用且草稿可編輯。
- 歸零且仍在收件時，送出重新開放並保留原草稿。已停止收件時顯示該狀態並阻止送出。
- 只顯示本組權限與收件狀態，其他組的身分、草稿與判分沿用既有角色限制。
