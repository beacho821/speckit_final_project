# 驗收結果：教師定案與學生倒數提示

**驗收日期**　2026-11-23  
**環境**　Windows、Node.js 26.13.1、Vitest 5.1.0、無頭 Microsoft Edge。瀏覽器以獨立的本機測試教室、虛構分組與多子題測試資料驗收。

## 指令與結果

| 指令 | 結果 |
| --- | --- |
| `npm run typecheck` | 通過。 |
| `npm run build` | 通過，產出前端與後端建置。 |
| `npm test -- --maxWorkers=2 --testTimeout=15000` | 56 個測試檔、208 個測試通過。首次以預設並行度執行時，一項既有 `.env` 設定測試超過 5 秒時限。降低並行度並提高時限後全數通過。 |
| `node coverage/qa007/browser-check.mjs` | 使用暫存驗收腳本、實際建置頁面與本機 Express，SC-001 至 SC-004 通過。亦可依[驗收指南](quickstart.md)重跑操作。 |
| `git diff --check` | 通過。 |

## 成功標準

| 標準 | 驗收結果 |
| --- | --- |
| SC-001 | 無人送答時列出待補答題號，空白不能定案，滑鼠與 Enter 都能將焦點放到第一個待補答欄位。部分答對時只列第二子題，補答後可定案。全對回合可直接定案並顯示勝組。 |
| SC-002 | 從超出一個畫面高度的題組頁尾操作，原區域顯示儲存及定案的處理中、成功和拒絕。成功定案後焦點仍在同區，回饋在可視範圍內。瀏覽器使用受控的拒絕回應，並另以契約測試驗證伺服器拒絕時的資料。 |
| SC-003 | 同教室兩個教師分頁有兩筆相異補答。只解決一筆時仍禁止儲存，全部選完才儲存。另一分頁讀回第一筆保留已存值、第二筆保留草稿。舊版本拒絕後未寫入任何差異。相同值與再更新邊界由元件及單元測試涵蓋。 |
| SC-004 | 曾勝組等待期間可填答，不能提前送出。倒數歸零後手動送出，後端收到的原文含原有空白。另一回合在等待期間停止收件，倒數歸零也沒有送出紀錄。 |

元件測試另確認儲存回應遺失時，只有版本前進不算成功。定案回應遺失時，以新快照及同一回合封存結果判斷成功或可重試，等待確認期間沒有自動重送。對照[組件圖](../../diagrams/007-component.puml)、[類別圖](../../diagrams/007-class.puml)及[時序圖](../../diagrams/007-sequence.puml)後，已更新對應 PNG。

本功能的規劃驗收案例皆已完成。
