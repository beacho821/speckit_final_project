# 功能規格：教師定案與學生倒數提示

**功能目錄**　`specs/007-clarify-round-feedback`  
**建立日期**　2026-11-23  
**狀態**　草案  
**需求來源**　改善教師從結束收件、補答、儲存到定案的操作回饋，以及學生在公平等待期間的送出提示。

## 釐清紀錄

### 2026-11-23 問答

- Q: 如果兩個教師分頁修改了同一筆判分或補答，較晚儲存的分頁應如何處理這筆衝突？ → A: 並列最新已存值和目前草稿，讓老師逐筆選擇保留哪個值。

## 使用情境與驗收

### 使用情境 1 — 教師找出必填補答並確認定案（P1）

老師結束收件後，在「確認定案」旁看見還要補哪些題，並能直接跳到第一個待補答欄位。題組逐一檢查子題，教師可在條件滿足後定案。

**優先原因**　教師須完成當前回合，才能接續課堂流程。  
**獨立驗收**　分別建立無人送答、只有第二個子題無人答對、所有子題皆有人答對的回合，結束收件後檢查操作區。

1. **假設**兩題皆無人送答，**當**老師結束收件，**則**「確認定案」旁依畫面題目順序顯示兩個待補答的完整題號。分別以滑鼠和鍵盤啟動前往補答的控制項，畫面移至第一個待填欄位且焦點落在該欄位，可立刻輸入。（FR-001、FR-002）
2. **假設**老師留白或只輸入空格、換行等空白字元，**當**檢視定案操作，**則**畫面列出待補答題號及下一步，且無法定案。若嘗試儲存的補答僅含空白，該值仍不算有效補答，回合保持待審核。（FR-001、FR-003）
3. **假設**第一個子題有具資格組別答對，第二個子題僅有錯答或僅有已取消資格組別答對，**當**老師查看審核畫面，**則**只列第二個子題為待補答。老師填寫並成功儲存後，若無其他阻擋條件，即可定案。（FR-001、FR-003）
4. **假設**兩個子題分別有不同的具資格組別答對，且無尚未儲存的修改，**當**老師查看審核畫面，**則**可直接定案。若沒有任何單一具資格組別答對整個題組，成功後顯示「無勝組」。（FR-003、FR-006、FR-008）

### 使用情境 2 — 教師在操作位置看到儲存與定案結果（P1）

老師在長題組頁尾能看出修改是否已儲存、能否定案，以及處理完成後的結果。兩個教師分頁同時審核同一回合時，老師能核對差異並保留輸入。

**優先原因**　老師需要在同一操作位置判斷下一步，避免錯過錯誤或重複提交。  
**獨立驗收**　使用需捲動至頁尾的題組，分別演練儲存成功、分頁衝突、定案成功及失敗。

1. **假設**老師修改了判分或補答，**當**修改尚未儲存、正在儲存、或收到成功結果，**則**操作區逐一顯示對應狀態。提交期間不接受重複操作。儲存成功後於同一處顯示可定案或目前仍缺的條件。（FR-003、FR-004）
2. **假設**兩個教師分頁對同一回合的兩筆補答各自輸入不同內容，且其中一頁先儲存，**當**另一頁核對最新內容，**則**兩筆都並列最新已存值和目前草稿，並標明完整題號。教師可在第一筆保留已存值、第二筆保留草稿。只選完一筆時，儲存與定案仍受阻擋。選完全部後，老師可儲存選定的內容，重新開啟審核時可看到兩筆選擇對應的結果。（FR-005）
3. **假設**老師從頁尾按下可用的「確認定案」，**當**定案送出並成功，**則**在原操作所在的位置先看到「定案中」，回應後看到「已定案」與勝組名稱或「無勝組」。結果可在目前位置閱讀，焦點不會被移到頁首。（FR-006）
4. **假設**老師從頁尾儲存或定案，**當**操作遭拒，**則**同一操作區顯示原因及可執行的下一步，保留輸入，且被拒的操作未生效。若斷線使結果暫時無法確認，則先顯示「結果待確認」，核對回合狀態後再顯示結果或允許重試。（FR-004、FR-007）

### 使用情境 3 — 學生確認等待原因並送出原草稿（P2）

學生看到其他組別的優先送出時段及自己的剩餘等待秒數，等待期間可先填答，資格開放後可送出原草稿。

**優先原因**　學生需分辨公平等待和送出故障，並知道等待時仍可作答。  
**獨立驗收**　在同一活動中讓一個已勝出的組別和一個尚未勝出的組別參與下一回合，觀察兩組送出權限。

1. **假設**本組依公平規則須等待，**當**回合開放，**則**在送出控制項旁看到其他組別優先、本組可先填答，以及剩餘整秒數。等待期間可輸入草稿，且無法提前送出。（FR-009）
2. **假設**本組在最後一秒已填妥答案，**當**優先時段結束且回合仍在收件，**則**送出控制項自動開放，原草稿完整保留，學生可手動送出並看到收件確認。（FR-010）
3. **假設**本組本來即可送出，**當**回合開放，**則**不顯示等待提示。若老師在倒數結束前停止收件，學生端須顯示已停止收件，且倒數歸零時不得重新開放送出。（FR-009、FR-010）

### 邊界情況

- 有人送答但全部答錯、所有答對者被取消資格、僅部分子題有正確作答，都依完整題號列出目前需補答的子題。改判或恢復資格後，待補答清單須反映新判分；若草稿因而不再適用，仍可查看或複製。
- 儲存失敗保留改判和補答，且不把未確認的修改顯示為已儲存。定案遭拒時，以最新回合狀態判斷是否可重試。
- 若兩個分頁將同一筆資料改成相同值，該筆無須選擇。沒有衝突的草稿仍可儲存，另一分頁已儲存且當前分頁未修改的項目採用最新值。若核對期間同一筆的已存值再次改變，須顯示更新後的值並要求重新核對該筆。
- 學生停留在同一回合期間，倒數更新不清空草稿。回合已停止收件時，即使倒數到零也不能送出。

## 需求

### 功能需求

| 編號 | 可驗收行為 |
| --- | --- |
| FR-001 | 「確認定案」旁須按顯示順序標出每個沒有具資格組別答對且缺少有效補答的完整題號，並說明先補答、再儲存的順序。每個子題獨立判斷，純空白視為未填。 |
| FR-002 | 有待補答欄位可編輯時，教師可用滑鼠或鍵盤從操作區直接移至第一個待填欄位，並在該欄取得輸入焦點。 |
| FR-003 | 若仍欠有效補答、有尚未儲存的修改、待核對較新的判分或已有相關操作處理中，須阻止定案並就地說明原因。當每個子題已有符合規則的正確答案或已儲存的有效補答，且審核內容已確認，即開放定案。 |
| FR-004 | 判分與補答操作區須區分尚未儲存、儲存中、已儲存可定案、已儲存仍缺條件，以及儲存失敗。等待確認時不可重複提交，遇到失敗須保留輸入及顯示下一步。 |
| FR-005 | 另一教師分頁儲存判分或補答後，當前分頁須保留未儲存輸入。若兩個分頁將同一筆修改為不同值，須按完整題號並列最新已存值與目前草稿，判分另標明組別。每筆衝突須由老師明確選擇保留已存值或草稿值。在所有衝突處理完之前，須阻止儲存與定案。選擇只更新待儲存內容，須經老師儲存才會生效。 |
| FR-006 | 定案操作區須在同一位置提供進度及成功回饋。成功時顯示目前回合已定案，以及勝組名稱或「無勝組」。 |
| FR-007 | 定案遭拒時，在操作位置顯示原因和可執行的下一步，且不得由這次拒絕操作變更定案狀態。結果不明時先提示待確認，依最新狀態提供結果或重試入口。 |
| FR-008 | 判分、資格、補答、勝組與公平等待沿用課堂現行規則。題組勝組為符合資格且全數答對的最早送出組。無符合條件的組別時顯示「無勝組」。 |
| FR-009 | 確實受到現行公平規則限制的學生組別，須在送出位置看到其他組別優先、可先填答及剩餘整秒數。等待期間保留可編輯的草稿並阻止提前送出。 |
| FR-010 | 等待時間歸零且回合仍收件時，學生可手動送出原草稿。已停止收件時須顯示該狀態並阻止送出。 |

### 主要實體

- **回合審核**　同一回合的題目與子題、已收答案、組別資格、判分與老師補答。
- **教師審核草稿**　教師在目前分頁尚未儲存的判分和補答，以及需核對的最新已儲存內容。
- **定案結果**　已完成定案的回合與勝組判定。
- **學生作答草稿**　同一組別在目前回合尚未送出的完整輸入，以及該組剩餘的公平等待時間。

## 成功標準

### 可衡量成果

- **SC-001**　3 種審核情境（無人送答、僅第二子題欠補答、各子題皆已答對）的待補答題號及定案可用性皆正確。兩個缺答情境以滑鼠和鍵盤各試 1 次，均能以 1 次啟動定位第一個待填欄位。
- **SC-002**　從長題組頁尾分別演練儲存成功、儲存失敗、定案成功與定案遭拒共 4 個案例。每次都在操作處看到當前狀態及結果，回到頁首尋找回饋的次數為 0。
- **SC-003**　以兩個教師分頁重現 2 筆互異的補答衝突。兩筆皆須顯示最新已存值與草稿值，只解決第 1 筆時儲存與定案均不可用。分別選擇保留已存值與草稿值並儲存後，兩筆結果須與各自選擇一致，未經選擇的衝突覆蓋次數為 0。
- **SC-004**　在 1 次等待後送出及 1 次等待中停止收件的驗收中，提前成功送出次數為 0。持續收件的案例在倒數歸零後，送出內容須與倒數結束前草稿逐欄一致。

## 假設

- 本功能範圍為現有教師審核及定案操作區、學生作答與送出區。驗收使用具授權的教師分頁及同一活動的學生分頁。
- 待補答順序依教師畫面所顯示的題目順序。按鈕旁使用簡短正體中文說明狀態與可執行動作。
- 驗收使用模擬答案及測試分組，保留現有角色權限。
