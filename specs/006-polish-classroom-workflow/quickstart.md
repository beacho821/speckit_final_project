# 快速驗收｜改善教室操作與活動結算

## 環境與指令

從專案根目錄執行，使用 Node.js 22.12 以上。依 [README](../../README.md) 準備本機 `.env` 和測試用教師密碼。HTTP 測試須可監聽本機暫用連接埠。使用測試教室、測試用學生與測試學習單。一般匯入可用 [混合題 XLSX](../002-classroom-workflow-fixes/references/mixed-questions.xlsx)，Google 回填的自動化測試可使用替身。SC-003 的實際回填驗收須另備有編輯權的 Google 試算表測試副本。

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run dev
```

開啟終端顯示的前端網址，預設為 `http://127.0.0.1:5173`。用有獨立教師與學生工作階段的瀏覽器進行手動驗收。規劃基準的型別檢查通過，`npm test` 在允許本機監聽時通過 55 檔、179 項。以下新增行為在實作後驗收。

## 一、分組預設與投影（FR-001 至 FR-003、SC-001）

1. 登入並建立兩間有不同組名及題目的測試教室。確認新建後進入分組管理，返回列表後重新選取亦同。明確導覽至題目管理與控制台時，頁面及目前選取標示一致。
2. 兩間教室各從三個工作區開啟投影，記錄六次結果。每次切換教師工作區、重新整理投影分頁一次。驗證原教室內容仍可取得，收件更新只出現在正確教室。
3. 在負責取得資料的教師頁模擬 5 秒離線並送達瀏覽器離線及恢復連線通知。偵測中斷後應保留最後畫面並標示「重新連線中」。服務已可存取時，自恢復連線通知起 10 秒內顯示最新狀態。再以假時計模擬未發出離線／恢復通知且本次請求一直無回應，在 25 秒期限前讓下一次請求可成功，從偵測逾時起 10 秒內取得完整快照。兩種情況均無登入提示，資料版本相同也能恢復。另保持離線超過 10 秒，驗證從偵測時點起第 10 秒清除內容、重連提示仍在。
4. 驗證開啟後尚無快照時只顯示載入或重連。保持重連畫面時由原教師頁登出，驗證投影立即清除。以獨立未登入分頁開啟投影網址，應只見指引。另驗證原教師頁關閉、彈出視窗被阻擋及同教室開始新活動。
5. 自動化測試使用假時間核對 9,999 與 10,000 毫秒、心跳不延長截止、異常來源訊息遭忽略、正常的長輪詢 `204`、同版恢復及撤權。另保留公開欄位與跨教室隔離的 HTTP 測試。

## 二、題卡儲存、刪除及排序（FR-004 至 FR-006、SC-002）

1. 選入三張未開放的學習單題卡，包含兩部分題組，另準備已開放題與手動題。安排三位教師試用者各在 90 秒內完成編修並儲存、拖曳並指出落點，以及取消刪除。核對新內容、順序及卡片檢視。
2. 修改題組兩部分後一起儲存。再清空第二部分的答案並重試。驗證第二次維持編修及輸入，有修正提示，讀回第一和第二部分均維持上次已保存版本。使用兩個教師分頁測試版本競爭，以測試替身模擬存檔失敗，核對不部分保存。再分別模擬儲存回應遺失且已寫入、儲存回應遺失但內容有差異。重新同步後，第一種應退出編修並顯示已存內容，第二種應保留草稿並提示核對。兩種都不自動重送。
3. 以滑鼠與觸控拖曳，並用鍵盤操作箭頭，核對預覽、落點與持久化順序。測試拖出範圍、取消、只有一張可排序卡及開始拖曳後目錄版本變更。原順序或最新有效順序應維持，手動題及已開放題維持既有位置規則。
4. 以紅色垃圾桶按鈕確認刪除未開放卡，核對題卡和清單都移除。驗證取消後題卡維持且鍵盤焦點回到原入口。核對圖示名稱可由輔助工具讀出。

## 三、結算與活動歷史（FR-008、FR-009、SC-003）

1. 分別在尚未開題、收件中、待審核及已定案時檢查結算入口。只有無進行中或待審核回合時能進入。比對結算外三項操作均不可見，進入與退出沒有寫入、匯出或切換副作用。
2. 使用 Google 測試替身驗證有已定案答案時的回填流程、資格與錯誤處理。另以有編輯權的 Google 試算表測試副本實際回填一次，核對指定儲存格與已定案答案相符，記錄 SC-003 的結果。若缺少測試副本或權限，記錄實際回填為未驗收並附原因。以無 Google 原稿但已有定案的活動下載 CSV，核對只含目前活動資料。驗證尚無定案紀錄時顯示空狀態，仍可開始新活動。
3. 驗證回填佔用期間不可開始新活動。取消確認會保留原場。確認成功後回到新場主持畫面，結算收起。核對原場定案、沿用清單與分組、新加入碼及舊加入碼失效。
4. 在兩個教師頁面驗證開題、換場與確認對話框的競爭。過期操作提示原因，且不得操作到非預期的新活動。模擬切換回應中斷並核對實際活動後，再決定是否允許重試。

## 四、學生判定與公布範圍（FR-007、SC-004）

1. 以 360 像素寬開啟學生歷史，核對答對、答錯、未作答及判定缺值各一筆，包含題組各部分。有答且判定正確為綠色「正確」，有答且判定錯誤為紅色「錯誤」並保留正解。其餘依 [介面契約](contracts/ui.md) 呈現。
2. 讓三位學生試用者各在灰階下分辨答對、答錯與未作答。待審核時驗證畫面及學生結果請求無正解與判定。定案後驗證僅本組當場結果可見。
