# 實作計畫｜改善教室操作與活動結算

**目前分支**　`main` · **功能識別**　`006-polish-classroom-workflow` · **日期**　2026-11-20 · **規格**　[spec.md](spec.md)

## 摘要

教師從教室列表進入分組管理，投影維持同教室的唯讀畫面並分辨載入、中斷及登出。題目管理使用圖示、整卡儲存及可預覽落點的拖曳。老師控制台主動開啟結算後才顯示課後操作，學生歷史依已公布的本組判定顯示正確或錯誤。

## 技術背景

| 項目 | 現況與設計 |
| --- | --- |
| 語言與版本 | Node.js 22.12 以上與 TypeScript。版本依專案的 `package.json` 和鎖定檔。 |
| 主要相依 | 沿用 React、Vite、Express、ExcelJS、Google Sheets、Pointer Events 及同源視窗訊息。 |
| 儲存 | 沿用每教室 JSON 原子存檔、教室交易及原有題目版本。投影與結算檢視僅需頁面記憶體。 |
| 測試 | Vitest、jsdom、本機 HTTP 契約／整合測試、桌面投影及實際觸控驗收。 |
| 目標平台 | 既有 Web 服務與桌面教師、獨立投影及學生瀏覽器。 |
| 專案類型 | 既有 Web 應用，共用前後端 TypeScript 型別。 |
| 效能目標 | 以 SC-001 至 SC-004 為準。投影偵測到中斷後保留畫面最多 10 秒，服務可存取時，從瀏覽器恢復連線通知起 10 秒內更新。若無連線通知且舊請求無回應，按 SC-001 從偵測逾時起驗收 10 秒內更新。 |
| 限制與範圍 | 沿用原教師頁授權、投影公開欄位、既有回合與資料隔離規則。整卡 PATCH、結算檢視及呈現變更涵蓋本規格九項需求。 |

## 階段 1｜設計與契約

| 對應需求 | 實作設計 | 驗證重點 |
| --- | --- | --- |
| FR-001 | 教室列表的共同入口導向分組管理，題目管理及控制台各用原網址。 | 新建／既有教室預設頁、明確工作區導覽及焦點。 |
| FR-002、FR-003 | 原教師頁持續取得經授權篩選的投影。視窗訊息包含明確狀態，按首次中斷時間限制快照，重連後讀取完整版。 | 初載、重整、兩室隔離、有效的 `204`、有通知的 5 秒斷線、無通知的請求逾時、各自的恢復起點、10 秒保留上限與撤權。 |
| FR-004 至 FR-006 | 整卡 PATCH 完整驗證後使用既有教室交易一次保存。題卡以圖示操作，排序沿用完整可移動卡片序列及目錄版本。 | 題卡成功關閉、待確認後依最新已存內容判定退出或保留草稿、並行及存檔失敗、刪除、滑鼠／觸控／鍵盤落點。 |
| FR-007 | 學生歷史依既有已公布結果呈現文字與顏色。 | 答對、答錯、未作答、判定缺值、待審核與本組資料界線。 |
| FR-008、FR-009 | 控制台依目前活動的同步階段開啟結算。原本的回填、CSV、活動切換及封存可由此操作。 | 狀態停用與空狀態、回填互斥、Google 測試副本實際回填、跨頁失效、取消、確認與舊紀錄保存。 |

[資料模型](data-model.md)列出狀態及驗證規則。[HTTP 契約](contracts/http.md)與[介面契約](contracts/ui.md)界定既有介面、新增整卡儲存及畫面行為。[快速驗收指南](quickstart.md)包含基準測試結果、實作後指令及可判定成敗的驗收案例。
