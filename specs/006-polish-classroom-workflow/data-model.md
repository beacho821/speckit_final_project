# 資料模型｜改善教室操作與活動結算

設計以[類別圖](../../diagrams/006-class.puml)為基礎。沿用每間教室的活動存檔、活動識別與服務執行期識別。

## 教室、教師工作區與活動

| 實體 | 欄位及關係 | 生命週期 |
| --- | --- | --- |
| 教室 | `classroomId`、名稱、目前活動及零到多場封存活動。 | 從列表進入教室時選分組管理。工作區導覽依指定教室運作。 |
| 教室活動範圍 | `classroomId`、`activityId`、`activityEpoch`。 | 開始新活動會更換活動識別，服務重啟可能更換執行期識別。舊範圍的請求須重新取得教室位置。 |
| 活動 | 回合、`catalogRevision`、分組、學習單來源、題卡、出題清單及暫時的 `writebackInProgress`。 | 結算檢視不改變活動本身。切換活動時既有交易一次保存新場及舊場定案紀錄，依原規則沿用分組與完整出題清單、更新加入碼。 |

## 全班投影

| 欄位 | 說明 |
| --- | --- |
| `roomId` | 投影視窗固定的教室，對應原教師頁的視窗登記。 |
| 目前教室活動範圍 | 由教師頁持有，用於取得快照及活動切換時重新定位。 |
| 快照 | 沿用 `ProjectionView`。包括版本、教室名稱、公開題目、回合階段、各組收件狀態及已公布摘要。 |
| 顯示狀態 | 等待、正常顯示、重連、需重新開啟或未授權。 |
| 斷線時間 | 首次偵測到該次中斷時設定。截止時間為偵測時間加 10 秒。重試與心跳共用同一截止時間。 |

投影資料與重連狀態都在頁面記憶體。首次偵測可來自瀏覽器離線通知、網路請求失敗或逾時。恢復連線通知與逾時各自是 SC-001 指定情境的恢復驗收起點。成功取得同活動的完整快照即可結束重連。截止日前可保留上一張同活動的公開畫面，截止時清除畫面並繼續嘗試連線。首次載入前斷線沒有可保留的畫面。接到登出通知、確認未授權、確認活動換代或得知來源頁面不可用時，清除相應的舊快照。課堂階段仍依伺服器資料。 [投影介面契約](contracts/ui.md)

## 題目卡、題卡草稿與出題清單

| 實體 | 欄位及關係 | 驗證 |
| --- | --- | --- |
| 題目卡 | `CatalogUnit.id`、名稱與一至多個 `RoundQuestion`。每個部分保有 `questionKey`、`questionRevision`、題幹、標準答案、來源及來源填空識別。 | 單題是只有一個部分的卡片。整卡儲存檢查題卡存在、未開放且目前無收件中或待審核回合。保留可預覽的既有不完整題卡，整卡儲存時須補齊各部分。 |
| 題卡草稿 | 依教室活動範圍、題卡及各部分識別持有編修時的 `catalogRevision`、各部分的 `questionRevision`、輸入題幹與換行分隔的答案。 | 各部分的識別集合須完整且不重複。版本衝突時保留草稿，與最新題卡核對後才更新提交基準。失效草稿只供核對。 |
| 出題清單 | `queueUnitIds` 依序引用題卡。可排序集合是已進入清單且尚未開放的學習單題卡。 | 排序請求只提交該集合的一組完整排列，依同一次操作的 `catalogRevision` 驗證。保留手動題及已開放題的位置或既定顯示規則。 |
| 拖曳狀態 | 來源題卡、指標識別、操作起始版本、目前落點及移動預覽。 | 取消、失去指標擷取、離開有效區或版本失效時移除預覽。排序成功後才更新顯示的順序。 |

整卡驗證須先於任何變更。只更新實際修改的部分版本，並對整張卡的有效變更增加一次目錄版本。一次交易完成存檔後才更新教師檢視。儲存回應未送達時，暫存已送出的內容和活動、題卡及各部分識別。送出後的新完整快照須與原範圍和各部分識別一致，且已存題幹及標準答案完全相符，才能以已存資料結束編修。否則保留草稿供核對。無異動的有效請求可回傳目前卡片。保存題目、排序或開啟回合的並行操作共用既有教室交易與目錄版本。範圍、題號與回合快照識別沿用既有資料結構。 [HTTP 契約](contracts/http.md)

## 結算檢視與學生逐題結果

- **結算檢視**　只在控制台使用。依活動範圍記錄是否由教師主動開啟，以及切換對話框和操作待確認狀態。根據同步中的 `ActivityView.phase`、`closedRoundIds`、學習單來源、`writebackInProgress` 及本頁請求狀態判斷可用操作。離開控制台、確認活動變動或進入收件／審核時機時收起。
- **學生逐題結果**　沿用學生所屬組別的 `StudentRoundResultLine`。含 `questionNumber`、可為空的 `partNumber`、題幹、`ownAnswer`、`correct` 與 `publishedAnswer`。判定以公布資料為準，缺少本組答案或已定案判定時保留原有中性色和可公布資訊。題組依每個部分顯示。
