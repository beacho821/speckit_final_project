# 快速驗收｜調整教室操作流程

## 環境與指令

使用 Node.js 22.12 以上，從專案根目錄執行。以測試教室及假資料操作。由現有 `.env.example` 建立本機 `.env`（如已存在則直接使用）並設定 `TEACHER_PASSWORD`。本機 XLSX 驗收不需 Google 憑證。HTTP 測試環境須允許監聽本機暫用連接埠。

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run dev
```

瀏覽啟動終端顯示的位址，預設前端為 `http://127.0.0.1:5173`。若以手機連同區網驗收，依 `README.md` 設定區網監聽與前端位址。使用普通瀏覽器分頁、學生獨立瀏覽器工作階段及開發者工具的 360 像素裝置模式。可用 `specs/002-classroom-workflow-fixes/references/mixed-questions.xlsx` 與 `single-questions.xlsx`；若匯入題幹或答案缺漏，從卡片補足後再開題。

規劃時的專案基準為 `npm run typecheck` 通過，`npm test` 共 54 檔、169 項通過。下列驗收於實作完成後執行。

優先擴充既有題目、匯入、回合、投影及隱私測試。原測試對跨來源題號衝突、組別投影與學生全班結果的期望，改依新契約驗證。另保留公平等待、CSV、回填及既有教室恢復測試。

## 一、首次匯入、拖曳與正式題號（FR-004 至 FR-007、FR-009）

1. 建立測試教室與至少兩組，先透過對話框新增手動題甲。必填只輸入空白時應顯示修正提示，清單不增加。
2. 首次匯入混合題 XLSX，選入兩張卡（含一組兩部分），重按已加入卡時清單筆數不變。手動題仍在末端。直接選取卡片補齊題幹與標準答案。
3. 拖曳對調兩張已選的學習單卡，重新整理後順序一致。改以鍵盤還原再重做一次。嘗試拖曳至手動題之後或取消拖曳，原順序維持。
4. 在控制台逐題開放、結束及定案，依序得到第 1 題、第 2 題、手動題第 3 題。確認題組用正確的部分順序。刪除或編修已開放題時應拒絕，學生已收件與既有題號保留。
5. 以兩個教師頁載入同一清單。一頁異動後，另一頁從舊畫面排序或開題，應提示資料已更新，且只會保留有效異動。模擬寫入或回應中斷，核對重新同步後再試，不會重複新增或開放。

## 二、換場、刪除、重匯與存檔（FR-001、FR-004 至 FR-007）

1. 在至少一題已定案且尚有待開放題時，由控制台開始新活動。查閱上一場紀錄，新活動沿用完整順序，下一個開放回合編為第 1 題。重啟服務後也能恢復清單及已保存的題號。
2. 在新活動首題開放前刪除一張未開放卡，應同時從題目管理與清單消失。取消刪除另一張卡後仍存在。上一場定案題幹、答案及原正式題號與部分序號可查閱。拖曳順序與來源題號不同時，換場及重啟後老師仍看到原實際開放的編號。
3. 保留至少一張已選的學習單卡及一題手動題。開始重新匯入並取消，再用無效檔案重試。兩次都保留既有卡片與清單。確認後重新匯入有效檔案，應只看到新來源卡片，清單為空，舊活動紀錄仍可查閱。
4. 選入並開放首題後再試重匯，應提示已開題並維持內容。由測試夾具載入缺少新欄位的既有教室紀錄，查閱舊回合序號、題組及已公布結果。
5. 載入含未開放準備回合的舊版存檔，刪除該回合引用的題卡。重啟後教室可正常載入，題卡及準備回合都已移除，下一題可正常開放。模擬存檔失敗時，三項資料均維持。
6. 以自動測試的 Google 替身驗證重新排序後的回填仍對到來源填空，手動題只出現在 CSV 等原有成果。若有測試用 Google 副本及服務帳戶，依 README 執行一次實際讀取與回填。

### MVP 交付前的結果權限驗收

在兩組皆送答的活動檢查同一結果端點。待審核時學生讀取須遭拒。公布後兩組各自只看到本組逐題答案，既有學生歷史可正常呈現，教師仍可看全班資料。嘗試讀取其他活動或教室的回合時須遭拒。通過後才交付 MVP。

## 三、兩間教室的投影（FR-001 至 FR-003、SC-002）

1. 從三個教師工作區逐一驗證導覽順序、目前頁面與右側投影連結。以滑鼠及鍵盤啟用連結。教師頁保留原工作區，同一教室重開聚焦既有投影。
2. 在兩間有不同組名的教室，分別開啟投影並完成三次有效收件更新。記錄從收件操作到所屬投影顯示的時間，每次須在 2 秒內。另一間教室的收件顯示維持原值。
3. 驗證準備中題幹、學生姓名、學生加入碼及答案均無法由投影取得；定案後可見摘要。新活動在同一視窗顯示新活動狀態；登出後清空舊投影。以未登入的獨立瀏覽器直接開啟網址，應顯示教師入口提示。以原組別投影路徑驗證已移除的操作，並確認學生加入仍有效。

## 四、學生作答、歷史與權限（FR-008 至 FR-011、SC-003 至 SC-004）

1. 在 360 像素寬度下加入活動，填寫草稿後以導覽及瀏覽器歷史來回切換，依然保有同一回合輸入且無水平捲動。「歷史紀錄」只有已公布結果或空狀態。
2. 送出有效答案後切換頁面，回到作答須呈現伺服器收件的唯讀答案。停在歷史頁時開下一回合，應留在歷史頁；回作答時顯示新題且不帶入原草稿。
3. 定案一題正確、一題答錯，另驗證沒有作答的組別。逐項核對題幹標題、單題與題組編號、「已回答」及空行以下的判定或公布正解。
4. 用該組已驗證的學生工作階段檢查公布結果網路回應。核對僅含本組逐題結果。待審核、其他組別身分、其他教室或上一場活動的請求遵循 [HTTP 契約](contracts/http.md) 的可見性與授權。任一頁故障須看見錯誤與重試入口。

依 SC-001 與 SC-003 各安排至少三位試用者，記下完成或失敗的任務與耗時。對照三張 PlantUML 圖和 [資料模型](data-model.md) 記錄驗收結果。
