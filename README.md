# 課堂活動

每位老師可建立多間自己的教室，分別備課、分組、主持搶答、審核及投影。學生用加入碼與名稱進入對應教室，同組共用每回合首次有效送答與順位。每間教室的分組、成員、題目與歷史紀錄自動存入專案根目錄的 `classroom-data/`。

## 本機開發

需要 Node.js 22.12 以上與 npm。在專案根目錄執行：

```sh
npm ci
cp -n .env.example .env
# 使用編輯器在 .env 設定 TEACHER_USERNAME 與 TEACHER_PASSWORD
npm run dev
```

單一 `npm run dev` 同時啟動 API 與 Vite，開啟終端顯示的位址（預設 [http://127.0.0.1:5173](http://127.0.0.1:5173)）。啟動會讀取根目錄 `.env`，外部環境變數優先；`PORT` 控制 API，預設 3000，可設為 1–65535。前端可用 `npm run dev -- --port 5174` 更換連接埠。

Ctrl+C 關閉兩個服務。前端熱更新不重設活動；修改後端或 `.env` 後，重新執行指令才生效。重新啟動會自動載入教室。若上次仍在收件，回合轉為待審核，原答案及順位保留。`.env` 不納入版本控制，教師密碼與 Google 金鑰也不會存入瀏覽器儲存區。

## 使用流程

1. 主帳號由 `TEACHER_USERNAME` 指定（預設 `teacher`），密碼由 `TEACHER_PASSWORD` 提供，可用 `TEACHER_DISPLAY_NAME` 設定顯示姓名。在教室清單或教室內點選左下角的教師頭貼與姓名，即可開啟「教師帳號設定」。主帳號可以建立子帳號並選填教師姓名，未填時顯示登入帳號。子帳號須輸入目前密碼才能修改自己的密碼，儲存後須以新密碼重新登入。每位教師只能操作自己的教室，既有教室歸主帳號。登入後從「我的教室」建立教室，或選「恢復主持」繼續既有活動。進入教室會先開啟「分組管理」，每間教室可獨立進行搶答。
2. 在「分組管理 → 組別名單」可手動建組，或下載 Excel 範例，填好「組別」「名字」兩欄後匯入。匯入會新增缺少的組別及成員，保留原有名單。同組同名可在名字前加座號，例如「01 王小明」「12 王小明」。學生以該組加入碼與完整名字進入教室。首題前可逐人移組，學生原分頁會切到新組，重新整理也會保留。移除成員會撤銷其原登入。
3. 在「題目管理」匯入本機 XLSX（上限 10 MiB）或 Google 試算表，按「確認加入出題清單」完成匯入。匯入預覽、手動新增題目，以及用鉛筆編修單題或題組時，都可開啟「AI 產生建議答案」。視窗只列出有題幹且標準答案空白的小題。勾選後按「產生建議」，核對標準答案與其他可接受答案，再按「加入標準答案」填入草稿，每行一種答案。可繼續編修或留空，最後依原流程確認匯入或儲存題卡。手動新增的題目會加到清單末端。尚未開放的題目可拖曳卡片頂端的長條把手，或使用箭頭圖示調整順序。
4. 到「老師控制台」開放下一題。題號依實際開放順序編定。首回合開始後，來源學習單鎖定，老師仍可手動新增組別或匯入 Excel 補充名單。收件中的回合可讓新組立即參加，收件後補建的組別從下一題參與。老師結束收件後可改判、取消或恢復資格。沒有標準答案的作答須由老師判定，再儲存判分。無人答對的小題預設留白；勾選補答可使用建議標答或自行填寫，隨定案封存。定案後，學生的作答畫面會逐題顯示正確或錯誤。
5. 從教師導覽右側的「開啟教室投影」開啟全班投影。偵測到斷線時，投影標示重新連線並保留最後畫面最多 10 秒。學生用導覽切換作答與本組已公布的歷史紀錄。
6. 控制台可查歷次定案結果。完成進行中的回合與審核後，按「結算」可預覽最終排名、回填、下載目前活動的 CSV、公布結算或開始新活動。按「公布結算」後，教室投影與學生端會突出顯示前三名，直到老師開放下一題或開始新活動。「開始新活動」沿用分組和出題順序，舊答案仍保留，積分從零開始。刪除教室前會顯示受影響的紀錄。

每次開題重新分配提交時間。近期答對率 p 等於最近五個已定案題組中老師最終判對的小題數，除以這些題組的小題總數。不足五組時使用現有紀錄，未答或失格計零。上一題得標組等待 T = 5 + 3p² 秒，上上題得標組等待 0.6 × T 秒，其餘組別立即開放。連續得標只取 T，無人得標的回合也佔一題。例如兩組輪流得標且答對率均為 50%，上上題得標組等待 3.45 秒，上一題得標組等待 5.75 秒。教師與投影顯示各組的收件狀態與倒數。倒數期間學生可閱讀題目，倒數歸零後才開放填答與送出，伺服器依收到送答請求的時間決定收件與順位。

每次定案後，學生端與教室投影會同步更新積分與名次。單題答對得 1 分，答對組別中最快及第二快另得 2 分及 1 分。題組每答對一小題得 1 分，速度加分只發給答對最多小題的組別中最早送出的兩組，每組每回合最多獲得一次速度加分。取消資格、未送出或全錯的組別該回合得 0 分。總分相同時並列，並列前三名的組別一併顯示。

學生身分僅暫存在該分頁的 `sessionStorage`。重新整理先向伺服器驗證，斷線後重新取得課堂狀態。活動失效、登出或撤權後清除暫存。開始新活動或重啟伺服器後，請重新分發學生加入碼。

首次匯入保留手動題。首題開放前可確認重新匯入，成功後清除原有卡片與清單，包含手動題。取消或失敗則保留原資料。匯入結果待確認時，請等待同步後再操作。

AI 備題由後端讀取 AI_API_KEY、AI_MODEL，以及選填的 AI_BASE_URL（預設 https://api.openai.com/v1）。只在教師點擊產生時傳送該題題幹及指定小題。若顯示「AI 金鑰已過期」，請將新的 API 金鑰存入根目錄 .env 的 AI_API_KEY，重新啟動後端後再產生建議。題組遇到金鑰或額度問題時會暫停後續請求，已取得的建議仍可採用。

結算時，Google 回填使用已定案勝組原答及老師選擇的補答。使用本機 XLSX 時，在結算頁重新選取匯入時的原檔，即可下載保留其他工作表的結果副本。

若「作答」表頭橫跨 G、H 兩欄，小題列的 G 欄可放「（1）」「（2）」等編號，答案會填入同列 H 欄。單題若將 G、H 合併，答案會填入該合併格。移動整個作答區後，系統會依表頭和合併位置辨識。

Google 功能另需在 `.env` 提供 `GOOGLE_SERVICE_ACCOUNT_JSON`（服務帳戶 JSON 檔案路徑，可使用相對於專案根目錄的路徑），並分享工作表給該服務帳戶。讀取用檢視權限，回填需編輯權限；建議使用獨立教師副本。純本機 XLSX 不需 Google 設定。同一張工作表一次處理一筆回填。若工作表忙碌，請等待後手動重試。

## 建置與驗證

```sh
npm run typecheck
npm test
npm run build
npm start
```

建置後的 `npm start` 在 [http://127.0.0.1:3000](http://127.0.0.1:3000)（或設定的 PORT）供應前端與 API。HTTP 測試需要可監聽本機暫時連接埠。

需要從區網的學生裝置或教師投影測試時，先停止開發服務，再執行 `npm run build` 與 `HOST=0.0.0.0 npm start`。使用伺服器的區網位址及指定連接埠。

最新教室操作請參考 [009 驗收指南](specs/009-teacher-classroom-controls/quickstart.md)。其他流程可參考 [教室驗收指南](specs/004-redesign-classroom-ui/quickstart.md) 及 [實作驗證紀錄](specs/004-redesign-classroom-ui/validation-results.md)。
