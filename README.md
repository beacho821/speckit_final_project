# 課堂活動

老師可建立多間教室，分別備課、分組、主持搶答、審核及投影。學生用加入碼與名稱進入對應教室，同組共用每回合首次有效送答與順位。每間教室的分組、成員、題目與歷史紀錄自動存入專案根目錄的 `classroom-data/`。

## 本機開發

需要 Node.js 22.12 以上與 npm。在專案根目錄執行：

```sh
npm ci
cp -n .env.example .env
# 使用編輯器在 .env 設定 TEACHER_PASSWORD
npm run dev
```

單一 `npm run dev` 同時啟動 API 與 Vite，開啟終端顯示的位址（預設 [http://127.0.0.1:5173](http://127.0.0.1:5173)）。啟動會讀取根目錄 `.env`，外部環境變數優先；`PORT` 控制 API，預設 3000，可設為 1–65535。前端可用 `npm run dev -- --port 5174` 更換連接埠。

Ctrl+C 關閉兩個服務。前端熱更新不重設活動；修改後端或 `.env` 後，重新執行指令才生效。重新啟動會自動載入教室。若上次仍在收件，回合轉為待審核，原答案及順位保留。`.env` 不納入版本控制，教師密碼與 Google 金鑰也不會存入瀏覽器儲存區。

## 使用流程

1. 老師登入後從「我的教室」建立教室，或選「恢復主持」繼續既有活動。每間教室可獨立進行搶答。
2. 由教室管理進入「開啟分組管理」，新增組別並將學生加入碼分發給各組。老師也可在組別列取得專用投影加入碼。學生填入加入碼和名稱後會進入對應教室及組別。
3. 教室管理提供本機 XLSX（上限 10 MiB）、Google 試算表及手動題目。備妥題幹與標準答案後到老師控制台開放搶答。
4. 首回合開始後，當次活動的分組與來源鎖定。學生整組一次送出，依公平等待規則排隊。老師結束收件後可改判、取消或恢復資格，並對無合格正解的小題補答，再確認定案。
5. 由管理頁開啟全班投影視窗。組別投影裝置前往同一站點的 `/projection` 並輸入老師提供的投影加入碼。
6. 控制台可查歷次已定案答案。CSV 與 Google 回填操作目前活動。開始新活動後可調整沿用的分組，舊答案仍保留。刪除教室前會顯示受影響的紀錄。

學生本人身分僅暫存該分頁的 `sessionStorage`；重新整理先向伺服器驗證。斷線後取得完整現況，不會自動重送答案。登出、已知撤權或活動過期會清除暫存。刪組立即撤銷加入碼，重建同名組會取得新碼；開始新活動或伺服器重啟後，請重新分發學生碼與投影碼。

首回合前成功換學習單會清除舊選題／準備回合，保留組別及成員。若匯入回應遺失，畫面顯示「匯入結果待確認」，同步目前快照後才恢復匯入與開題，不自動重送匯入。

Google 功能另需在 `.env` 提供 `GOOGLE_SERVICE_ACCOUNT_JSON`（服務帳戶 JSON 檔案路徑，可使用相對於專案根目錄的路徑），並分享工作表給該服務帳戶。讀取用檢視權限，回填需編輯權限；建議使用獨立教師副本。純本機 XLSX 不需 Google 設定。同一張工作表一次處理一筆回填。若工作表忙碌，請等待後手動重試。

## 建置與驗證

```sh
npm run typecheck
npm test
npm run build
npm start
```

建置後的 `npm start` 在 [http://127.0.0.1:3000](http://127.0.0.1:3000)（或設定的 PORT）供應前端與 API。HTTP 測試需要可監聽本機暫時連接埠。

需要從區網的學生裝置或組別投影測試時，先停止開發服務，再執行 `npm run build` 與 `HOST=0.0.0.0 npm start`。使用伺服器的區網位址及指定連接埠。

參考 [教室驗收指南](specs/004-redesign-classroom-ui/quickstart.md) 及 [實作驗證紀錄](specs/004-redesign-classroom-ui/validation-results.md)。
